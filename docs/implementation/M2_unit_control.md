## 1. Цель и результат

**Цель:** научить юниты **двигаться как в хорошей RTS**: поворачиваться, объезжать препятствия, ездить группой, не застревать и не толкаться бесконечно. Это фундамент для боя (M4), экономики (харвестеры, M3) и ботов (M5). Одновременно игрок получает полноценное управление: выделение, группы, приказы.

**Что будет работать в конце вехи:**

1. Детерминированная тригонометрия: углы, направление юнита (facing), скорость поворота.
2. Карта в симуляции: типы земли и проходимость для пехоты, гусениц и колёс.
3. Поиск пути A* с сглаживанием, бюджетом вычислений на тик и очередью запросов.
4. Групповое движение: юниты приходят в точку «пятном», а не сбиваются в одну клетку.
5. Локальное избегание: резервирование клеток, ожидание, обход, перестроение пути при блокировке.
6. Пехота: до 5 бойцов в клетке на подклетках.
7. Команды: движение, стоп, атака-движение (атака — заглушка до M4), путевые точки, рассредоточение.
8. Клиент: выделение рамкой, двойной клик, группы Ctrl+1…9, курсоры, маркеры приказов, скролл камеры, заготовка миникарты, отладочные оверлеи путей и проходимости.
9. **300 юнитов** на карте 128×128 при 15 тиках/с, тик ≤ 4 мс на MacBook с M1.

**Как это выглядит для игрока:** выделил рамкой 40 танков и 20 пехотинцев, кликнул за лес — отряд объезжает лес, проходит через узкий мост по очереди и встаёт пятном у цели. Ctrl+1 — группа, 1 — снова выбрана.

## 2. Рамки

### Входит

- `FixedMath`: синус, косинус, atan2 по таблицам; тип угла `BAngle` (16 бит).
- Направление юнита (facing) и поворот с ограниченной скоростью, поворот башни — заготовка (поле и вращение к цели по команде, без стрельбы).
- `MapGrid` в симуляции: тип земли клетки, проходимость, множители скорости по локомоторам.
- Временный формат тестовых карт (ASCII) до появления настоящего формата в M7.
- Локомоторы: `Foot`, `Track`, `Wheel`.
- A* на клетках (8 направлений, октильная эвристика, целочисленные стоимости), сглаживание, бюджет узлов на тик.
- Групповое движение: распределение точек назначения вокруг цели.
- Локальное избегание: резервирование клеток, ожидание, вежливое отодвигание стоящих своих, перестроение пути.
- Подклетки пехоты (5 на клетку).
- Пространственный индекс в симуляции (бакеты).
- Команды `Move`, `Stop`, `AttackMove`, `Waypoints`, `Scatter`.
- Временные типы юнитов в коде (пехотинец, танк, джип) — до данных YAML в M3.
- Клиент: выделение, группы, курсоры, маркеры, миникарта-заготовка, оверлеи.
- Нагрузочный сценарий и бенчмарки.

### Не входит (и в какой вехе появится)

| Что | Где |
|---|---|
| Стрельба, цели, урон (атака в `AttackMove`) | M4 |
| Давка пехоты танками | M4 |
| Здания как препятствия | M3 (футпринт зданий блокирует клетки) |
| Харвестеры и их логика | M3 |
| Высоты, склоны, мосты в правилах | M7 |
| Иерархический поиск пути (HPA*) для больших карт | M7 (если A* не уложится в бюджет на 200×200) |
| Авиация, флот, ховер | M11 |
| Настоящая миникарта с радаром | M3 (радар), M6 (вид как в RA2) |
| Данные юнитов из YAML | M3 |

## 4. Технические решения

### 4.1. Углы и тригонометрия

**`BAngle` — «бинарный угол»:** `ushort`, 0…65535, где 65536 = 360°. Переполнение = естественный переход через 0°, поэтому сложение углов не требует проверок. Разница углов — `short` (знаковая, −180°…+180°) без ветвлений.

| Величина | Значение |
|---|---|
| 0 | Север (−Y в координатах карты, «вверх-вправо» на экране RA2) |
| Направление роста | По часовой стрелке (как compass) |
| 1 единица | ≈ 0,0055° |

**Таблицы:**

| Таблица | Размер | Содержимое |
|---|---|---|
| `SinQuarter` | 4097 значений `int` | sin для четверти круга с шагом 16 единиц `BAngle`, значения в формате `Fixed.Raw` (0…65536) |
| `AtanTable` | 1025 значений `ushort` | atan(t) для t = 0…1 с шагом 1/1024, результат в `BAngle` |

- `Sin(a)`: четверть по старшим битам, индекс по средним, **линейная интерполяция** между соседними значениями целочисленно.
- `Atan2(dy, dx)`: октант по знакам и сравнению |dx| и |dy|, отношение меньшего к большему в `Fixed`, поиск в `AtanTable` с интерполяцией, сборка угла.
- `Length(dx, dy)`: `IntMath.Sqrt(dx² + dy²)` на `long` (лептоны до ~50 000 по оси на карте 200×200 — без переполнения).
- `Normalize`: вектор длины `Fixed.One` через `Length` и деление.

**Генерация таблиц:** `tools/Rts.TrigGen` считает значения через `double` **один раз на машине разработчика** и пишет `TrigTables.g.cs` с литералами. Файл коммитится. В симуляции `double` по-прежнему запрещён — она только читает готовые целые числа, поэтому результат одинаков везде.

**Проверки:** «золотой» тест — контрольная сумма всех таблиц + выборочные значения; тест точности — сравнение с эталонными значениями (посчитаны заранее и лежат в тестовых данных) с допуском 2 единицы `Raw` для `Sin` и 8 единиц `BAngle` для `Atan2`.

### 4.2. Направление и поворот

| Поле юнита | Тип | Смысл |
|---|---|---|
| `Facing` | `BAngle` | Куда смотрит корпус |
| `TurnRate` | `ushort` | `BAngle` за тик (например, танк — 2048 ≈ 11°/тик) |
| `TurretFacing` | `BAngle` | Заготовка, вращается к цели в M4 |

**Правило движения с поворотом** (как в RA2 у техники):
- Если разница между `Facing` и направлением на следующую точку пути > 45° — юнит **стоит и поворачивается**.
- Если ≤ 45° — **едет и доворачивает** одновременно.
- Пехота поворачивается мгновенно (визуально — анимацией в клиенте).

Клиент теперь берёт угол модели из симуляции (интерполяция `BAngle` по кратчайшей дуге), визуальный поворот из M1 убирается.

### 4.3. Карта в симуляции

**`MapGrid`:** массивы размера W×H (структура массивов — быстрее и проще хешировать):

| Массив | Тип | Что |
|---|---|---|
| `Terrain` | `byte` (`TerrainType`) | Тип земли |
| `Blocked` | `bool`/битовая маска | Статическое препятствие (скала, дерево, позже — здание) |
| `VehicleOccupant` | `int` (EntityId или 0) | Кто стоит/зарезервировал клетку (техника) |
| `InfantryMask` | `byte` | Занятые подклетки (биты 0–4) |

**Типы земли (M2):**

| `TerrainType` | Foot | Track | Wheel |
|---|---|---|---|
| `Clear` (снег/трава) | 100% | 100% | 100% |
| `Road` | 100% | 100% | 125% |
| `Rough` (грязь, бездорожье) | 90% | 85% | 60% |
| `Trees` | 0 (непроходимо) | 0 | 0 |
| `Rock` | 0 | 0 | 0 |
| `Water` | 0 | 0 | 0 |

Таблица в M2 — в коде (`Locomotor`), в M3 переезжает в YAML. Проценты — целые, применяются к скорости через `Fixed`.

**Связь с M1:** маска земли клиента (слои снег/трава/грязь/дорога) и раскладка деревьев теперь **строятся из `MapGrid`**, а не задаются вручную. Деревья ставятся только в клетки `Trees`.

**Временный формат тестовых карт** (`TestMapParser`), одна буква — одна клетка:

```
# 16x8
. . . . R R R . . . . . . . . .
. T T . R . . . . ^ ^ . . . . .
. T T . R . . . . ^ ^ . . . . .
. . . . R R R R R R R R R R . .
```

`.` — Clear, `R` — Road, `~` — Rough, `T` — Trees, `^` — Rock, `W` — Water. Плюс строки с объектами: `unit Tank 3 5 player=0`. Используется в тестах и витрине M2. Настоящий формат — M7.

### 4.4. Поиск пути: A*

| Параметр | Решение | Почему |
|---|---|---|
| Граф | Клетки, 8 соседей | Как в RA2 |
| Срезание углов | Запрещено: диагональ только если обе соседние ортогональные клетки проходимы | Не протискиваться между двумя деревьями |
| Стоимость шага | Прямо 10, диагональ 14, умножить на 100 / (множитель скорости %) | Целые числа, дороги притягивают колёсную технику |
| Эвристика | Октильная: `(10·(dx+dy) + (14−20)·min(dx,dy)) × минимальный множитель стоимости локомотора` | Допустимая и согласованная для 8 соседей; домножение на минимальный множитель (например, дорога для колёс) сохраняет допустимость |
| Очередь | Собственная двоичная куча `MinHeap`, ключ `(f, h, cellIndex)` | Полностью определённый порядок при равных `f` — детерминизм не зависит от реализации .NET `PriorityQueue` |
| Занятость | Статика учитывается, движущиеся юниты — нет (их решает локальное избегание) | Пути стабильны, не перестраиваются от каждого встречного |
| Недостижимая цель | Путь к ближайшей достижимой клетке (по эвристике среди закрытых узлов) | Клик в скалу ведёт к краю скалы, как в RA2 |
| Ограничение | Максимум 20 000 раскрытых узлов на запрос | Защита от поиска через всю карту в тупик |

**Очередь запросов и бюджет (`PathRequestQueue`):**
- Юнит не ищет путь сам — ставит запрос в очередь.
- За тик обрабатывается не более **6 000 раскрытых узлов** суммарно. Незаконченный запрос продолжается на следующем тике **с того же места** (состояние поиска хранится).
- Порядок обработки — по `(тик запроса, EntityId)`.
- Пока путь не найден, юнит уже поворачивается в сторону цели (без ощущения задержки).
- Состояние очереди и незаконченных поисков входит в хеш (это часть состояния симуляции).

**Повторное использование:** юниты одной группы, стартующие рядом, получают общий «каркасный» путь: A* один раз от центра группы, затем каждый юнит строит короткий путь до ближайшей точки каркаса (если выигрыш подтвердится бенчмарком — иначе индивидуальные пути).

### 4.5. Сглаживание пути

- **«Натягивание нити»:** из текущей точки ищем самую дальнюю точку пути, до которой есть прямая видимость, пропускаем промежуточные.
- **Видимость** — целочисленный обход клеток по отрезку (supercover-растеризация): все клетки, которых касается отрезок, проходимы для локомотора, без срезания углов.
- Результат — список точек (`WorldPos`) с меньшим числом поворотов. Юнит едет по прямым между ними.

### 4.6. Групповое движение

**Проблема:** 40 танков с одной целью сбиваются в одну клетку и толкаются бесконечно.

**Решение — распределение точек назначения (`GroupDestinations`):**
1. Собираем свободные проходимые клетки вокруг цели по спирали (кольцо за кольцом), отдельно для техники и для подклеток пехоты.
2. Сортируем юниты группы по расстоянию до цели, затем по `EntityId`.
3. Жадно назначаем каждому ближайшую свободную клетку из собранных (с сохранением относительного расположения: юнит слева в группе стремится получить точку слева от цели — смещение относительно центра группы, ограниченное радиусом).
4. Каждый юнит получает свою точку назначения и свой путь.

Порядок полностью детерминирован (сортировки по целым ключам и `EntityId`).

**Скорость группы:** в M2 каждый едет со своей скоростью (как в RA2). Режим «строем со скоростью самого медленного» — открытый вопрос.

### 4.7. Локальное избегание: резервирование клеток

Техника занимает **одну клетку**. Двигаться в следующую клетку пути можно только после её **резервирования** (`Reservations`):

```
Хочу в клетку C:
  свободна            → резервирую, еду
  занята движущимся   → жду (до 8 тиков), затем пробую обойти соседней клеткой,
                         затем перестраиваю путь, считая C временно непроходимой
  занята стоящим своим → прошу его отодвинуться (он делает шаг в свободную соседнюю
                         клетку не по моему пути), жду
  занята стоящим чужим → перестраиваю путь в обход
```

- **Встречное движение** (два юнита хотят клетки друг друга): уступает юнит с большим `EntityId` — делает шаг в сторону.
- **Защита от вечных пробок:** счётчик ожидания; после 30 тиков без прогресса — новый путь с запретом занятых клеток; после 3 неудачных перестроений — юнит останавливается рядом с целью («прибыл, насколько возможно»).
- Резервирование снимается при выходе из клетки.
- Пехота резервирует **подклетку**, а не клетку. Техника и пехота не делят клетку (давка — в M4).

### 4.8. Подклетки пехоты

- В клетке 5 позиций: центр и 4 точки по диагоналям (смещение ±64 лептона от центра).
- Боец занимает подклетку; приходя в клетку, выбирает свободную ближайшую к направлению движения.
- Маска занятости — 5 бит на клетку.
- Если клетка заполнена, пехота использует соседние (через распределение точек назначения).

### 4.9. Пространственный индекс

- Сетка **бакетов 4×4 клетки**; в каждом — список `EntityId`, отсортированный по возрастанию.
- Обновляется при пересечении границы бакета (не каждый тик для всех).
- Запросы: «юниты в радиусе R от точки», «юниты в прямоугольнике». Результат всегда отсортирован по `EntityId`.
- Используется избеганием, распределением точек и (в M4) поиском целей.
- Индекс — производная структура: не входит в хеш (его можно восстановить из состояния), но тест проверяет, что он совпадает с полным перебором.

### 4.10. Команды

| Команда | Параметры | Поведение |
|---|---|---|
| `Move` | юниты, точка, `queue` | Распределение точек → пути. `queue = true` — добавить в конец маршрута |
| `Stop` | юниты | Сбросить путь и очередь приказов, освободить резервы впереди |
| `AttackMove` | юниты, точка | Как `Move`, но с флагом «атаковать по пути» (в M2 — без атаки, флаг сохраняется в состоянии) |
| `Waypoints` | юниты, точки[], `loop` | Маршрут по точкам, опционально по кругу (патруль) |
| `Scatter` | юниты | Каждый — в случайную (детерминированный ГСЧ) свободную соседнюю клетку |

`MoveUnitsCommand` из M0 переименовывается в `MoveCommand` с полем `queue`. Формат сериализации — версия 2, старые повторы M0 помечаются как несовместимые (это нормально до релиза; версия правил `simVersion` увеличивается).

**Ограничение:** до 256 юнитов в одной команде (размер пакета для сети в M9).

### 4.11. Временные типы юнитов

До данных YAML (M3) — набор в коде (`UnitArchetypes`):

| Тип | Локомотор | Скорость (лептонов/тик) | `TurnRate` | Размещение |
|---|---|---|---|---|
| `TestInfantry` | Foot | 18 | мгновенно | Подклетка |
| `TestTank` | Track | 40 | 2048 | Клетка |
| `TestJeep` | Wheel | 64 | 3072 | Клетка |

`SpawnTestUnitCommand` получает параметр типа.

### 4.12. Порядок внутри тика (обновлённый)

```
1. Команды тика T (сортировка, проверка, применение)
2. PathRequestQueue — обработка в пределах бюджета
3. MovementSystem:
   a. Повороты
   b. Попытки резервирования следующих клеток (в порядке EntityId)
   c. Перемещение на скорость × множитель земли
   d. Снятие резервов покинутых клеток, прибытие
4. SpatialIndex — обновление
5. Удаление мёртвых
6. T = T + 1, хеш
```

Резервирование в порядке `EntityId` — источник детерминизма в спорных ситуациях.

### 4.13. Хеш

Добавляются: `Facing`, `TurretFacing`, состояние `Mover` (путь, индекс точки, счётчики ожидания, флаги), очередь приказов юнита, резервирования и маски подклеток, `MapGrid` (один раз при старте — хеш карты, затем только изменяемые массивы), очередь запросов пути и незаконченные поиски. Тест-охранник полей из M0 распространяется на новые классы.

### 4.14. Клиент

**Выделение (`SelectionController`)** — состояние только клиента, не симуляции:

| Действие (классика RA2) | Результат |
|---|---|
| Левый клик по своему юниту | Выделить его |
| Протяжка левой кнопкой | Рамка: все свои юниты, чьи экранные позиции внутри |
| Shift + клик / рамка | Добавить / убрать из выделения |
| Двойной клик по юниту | Все свои юниты этого типа на экране |
| Левый клик по земле при выделении | `Move` |
| Ctrl + Shift + клик | `AttackMove` |
| Z + клики, затем клик без Z | `Waypoints` |
| Правый клик | Снять выделение |
| S / X | `Stop` / `Scatter` |
| Ctrl+1…9 | Назначить группу |
| 1…9 | Выбрать группу; двойное нажатие — камера к группе |
| Shift+1…9 | Добавить группу к выделению |

Альтернативная (современная) схема — в M6 вместе с настройками.

**Курсоры:** обычный, выбор, движение, нельзя (непроходимо / за краем карты), атака-движение. Подсветка при наведении на юнит.

**Обратная связь:** маркер приказа на земле (зелёный — движение, жёлто-красный — атака-движение), линии путевых точек для выделенных, отладочный лог «голосов» (настоящие голоса — M6).

**Камера:** из M1, плюс прыжок к группе, F1…F4 — закладки позиций (Ctrl+F1…F4 — сохранить).

**Миникарта (заготовка):** панель в правом верхнем углу: цвета земли из `MapGrid`, точки юнитов цветом команды, рамка видимой области, клик — переместить камеру. Без радара и тумана войны.

**Отладочные оверлеи (F-клавиши в debug-режиме):** проходимость по выбранному локомотору, пути выделенных юнитов, резервирования, бакеты индекса, статистика `PathRequestQueue` (узлов за тик, длина очереди).

### 4.15. Производительность

| Сценарий | Цель (MacBook M1) |
|---|---|
| 300 юнитов (100 пехоты, 150 танков, 50 джипов), карта 128×128, все получили приказ через карту | Тик ≤ 4 мс в среднем, ≤ 8 мс в пике |
| 300 юнитов стоят | Тик ≤ 0,5 мс |
| Один A* через всю карту 128×128 с лабиринтом | ≤ 2 мс |

**Бенчмарки** (`Rts.Simulation.Benchmarks`, BenchmarkDotNet): `Tick_300Units_Moving`, `AStar_Maze128`, `SpatialIndex_Query`, `Sin_Atan2`. Запускаются вручную, результаты пишутся в журнал. В CI — только «дымовой» прогон (что не падают), без порогов.

**Если не укладываемся:** профилирование → по порядку: кэш путей для групп, уменьшение бюджета узлов с растягиванием на тики, `Span`/массивы вместо списков, HPA* (переносится в M7).

## 6. Тесты

### Модульные

| Область | Что проверяем |
|---|---|
| `BAngle` | Сложение через 0°, разница со знаком, кратчайший поворот |
| `FixedMath` | Sin/Cos в 0°, 90°, 180°, 270° точно; точность на 10 000 случайных углах; Atan2 во всех 8 октантах и на осях; `Length` на больших значениях |
| `MapGrid` | Проходимость по таблице, границы карты |
| `TestMapParser` | Корректный разбор, ошибки на неверных символах |
| `MinHeap` | Порядок при равных ключах определён и стабилен |
| `AStar` | Длина пути = эталонной на 10 картах (открытое поле, стена, лабиринт, остров, U-ловушка); недостижимая цель — ближайшая клетка; запрет срезания углов |
| `PathSmoother` | Нет прохода сквозь препятствия; число точек не больше исходного |
| `Reservations` | Две техники не занимают одну клетку ни на одном тике |
| `GroupDestinations` | Уникальность клеток, детерминированность, проходимость |
| Команды | Сериализация v2 для всех 5 команд; валидация (чужие юниты отбрасываются) |

### Сценарные (headless, без Godot)

| Сценарий | Ожидание |
|---|---|
| Коридор 1 клетка, два танка навстречу | Оба проходят за ≤ N тиков, без вечного ожидания |
| Мост на 1 клетку, 20 танков | Все переходят по очереди |
| 40 танков в точку за лесом | Все доезжают, ни один не застревает > 30 тиков без движения |
| Пехота 30 бойцов в одну точку | Распределены по подклеткам, без наложений |
| Клик в скалу | Юниты останавливаются у края |
| Путевые точки с `loop` | Патруль 3 круга по маршруту |

Каждый сценарий также проверяет **инварианты на каждом тике**: нет двух техник в клетке, нет пехоты на чужой подклетке, все юниты на проходимых клетках.

### Детерминизм

- «Золотые» значения M2: хеш таблиц тригонометрии; хеш после 3000 тиков сценария «300 юнитов, приказы по ГСЧ».
- Независимость от бюджета: один и тот же сценарий с бюджетом A* 1 000 и 100 000 узлов даёт одинаковые **пути** (но время прибытия может отличаться — сравниваем финальные позиции после установления).
- Повтор: запись сценария → проигрывание → совпадение хешей.

### Производительность

Бенчмарки раздела 4.15, ручной запуск, результаты — в журнале.

## 8. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Пробки и «танцы» юнитов в узких местах | Высокая | Сценарные тесты с первых шагов, отладочные оверлеи, итерации правил ожидания |
| A* не укладывается в бюджет на больших картах | Средняя | Бюджет с продолжением, общий каркасный путь для группы, HPA* в M7 |
| Неточность табличной тригонометрии даёт «дрожание» направления | Низкая | Интерполяция, допуски в тестах, сглаживание поворота в клиенте |
| Резервирование выглядит «дискретно» (юниты дёргаются по клеткам) | Средняя | Движение по сглаженным прямым, резерв — только как разрешение, визуал интерполируется |
| Изменение формата команд ломает повторы M0 | Точно | Ожидаемо, `simVersion` увеличивается; до релиза совместимость повторов между версиями не обещаем |
| Классическая схема управления неудобна современным игрокам | Средняя | Альтернативная схема в M6 |
