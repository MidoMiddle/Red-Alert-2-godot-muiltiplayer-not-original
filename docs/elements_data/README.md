# Данные элементов карты: схема и индекс

Черновики записей для элементов карт из `docs/`: 115 элементов в десяти наборах. Файлы здесь игра не читает. Загрузчик смотрит только `game/data` (см. `docs/formats/data.md`). Черновики — заготовка для записей, которые появятся в `game/data/` при переводе объектов карты на YAML (шаг 14а M3, см. раздел «Переход» ниже).

Значения в черновиках совпадают с кодом: `src/Rts.Simulation/Map/MapObjectTypes.cs`, `src/Rts.Simulation/World/BuildingTypes.cs`, `src/Rts.Simulation/Map/Bridge.cs`. Где документ расходится с кодом или значения в документе нет, в черновике стоит комментарий `#`.

## Статусы

| Статус | Смысл |
|---|---|
| в игре | есть в коде и на карте-примере `game/maps/test/elements.txt` |
| в коде | вид уже был в коде до доработки M7 (шаги 5–7) |
| ждёт M11a | нужна механика M11a: гарнизоны, захват, инженеры, мины, ящики, доход зданий |
| ждёт M11b | флот, амфибии, вертолёты |
| ждёт M11e | климат (пустыня, пляж, умеренный, город, побережье) или финальный арт |
| ждёт решения N | открыт пункт владельца N (см. таблицу ниже) |
| ждёт механики | нужна механика, которой нет ни в одной вехе |
| ждёт M11 | элемент назначен M11 без подэтапа (жители, гражданская техника, часть объектов M11); решает владелец |
| нет записи | игрового объекта нет: декаль, житель, освещение, триггер, погода |

Если элемент ждёт сразу нескольких, статусы перечисляются через запятую.

## Схема записи

Одна запись — один игровой объект. Ключ верхнего уровня — `id` (snake_case, как в коде). В записи только ключи из таблицы; всё остальное — комментарием `#`.

| Ключ | Значение | Соответствие в коде |
|---|---|---|
| `kind` | `map_object`, `neutral_building`, `bridge` | `MapObjectKind`, `BuildingKind`, `BridgeKind` |
| `hp` | целое; `0` — неразрушим | `MaxHp` |
| `footprint` | `[ширина, высота]` в клетках, только для зданий | `Width`, `Height` |
| `blocks` | список: `foot`, `track`, `wheel`, `amphibious`, `naval`, `hover`; или `all` — все | `BlockMask` |
| `crushed_by` | список передвижений, которые сминают объект | `CrushMask` |
| `speed` | словарь «передвижение: процент»; без ключа — 100 % | `Speeds` (замедление на объекте) |
| `stump` | `true` или `false`: остаётся пень | `LeavesStump` |
| `garrison` | целое; `0` — гарнизона нет | `Garrison` (логики до M11a нет) |
| `capturable` | `true` или `false` | `Capturable` (логики до M11a нет) |
| `explodes`, `burns` | `true` или `false`: взрыв и горение, пока только данные | — |
| `segment_hp` | целое, для моста | `BridgeType.SegmentHp` |
| `height` | число в единицах клиента, для вида | `game/scripts/Terrain/Buildings.cs` |

Пример объекта:

```yaml
anti_tank_hedgehog:
  kind: map_object
  hp: 400
  blocks: [track, wheel]
  crushed_by: []
```

Пример здания:

```yaml
neutral_factory_hall:
  kind: neutral_building
  footprint: [4, 3]
  hp: 800
  garrison: 6
  capturable: false
```

## Прочность по классам

Предложение, баланс — в M4:

| Класс | Объект карты | Здание |
|---|---|---|
| низкая | 50 | 300 |
| средняя | 400 | 800 |
| высокая | 1500 | 1500 |

`hp: 0` ставим только для вида, у которого в модели есть признак неразрушимости (сугроб). Если документ говорит «неразрушим», а признака нет (градирня), ставим класс «высокая» и комментарий `# документ: неразрушим, признака в модели нет`.

## Файлы

- `drafts/<набор>.yaml` — записи набора. Ключ — `id`, значения — по схеме.
- `index/<набор>.md` — таблица элементов набора: папка, статус, блокер, будущий файл, заметка. Сюда же идут элементы без записи.
- Один `id` — одна запись. Если элемент использует уже существующий вид, запись не дублируется: в индексе указывается набор, где она лежит.
- Декали и жители записей не имеют: вида `decal` в схеме нет.

## Переход в game/data (шаг 14а M3)

Будущая раскладка, которая совпадёт с черновиками:

- `game/data/climates/<климат>/map_objects.yaml` — объекты климата;
- `game/data/neutral/buildings.yaml` — нейтральные и технические здания;
- `game/data/neutral/objects.yaml` — препятствия и промзона, не привязанные к климату.

Переход делается отдельным шагом после M8. Тогда меняются загрузчик, хеш данных и пин в тестах.
