## 1. Цель и результат

**Цель:** превратить «поле с юнитами и базой» в войну. Юниты и здания получают здоровье, оружие и броню, стреляют сами и по приказу, гибнут, базы разрушаются. Появляется туман войны: игрок видит только то, что видят его юниты.

**Что будет работать в конце вехи:**

1. Модель боя в духе RA2: оружие → снаряд → боеголовка → таблица «боеголовка против брони» (Verses).
2. Снаряды двух классов: мгновенные (пули, тесла-разряд) и летящие (снаряды по дуге, ракеты с наведением). Всё детерминировано.
3. Урон по площади со спадом, давка пехоты танками.
4. Автоматический выбор цели с приоритетами угрозы, режимы поведения (агрессивный / охрана / удерживать позицию).
5. Приказы «атаковать», «принудительная атака», настоящий «атака-движение».
6. Гибель юнитов, разрушение зданий, состояния повреждений.
7. Оборонительные здания Союза: пулемётный бункер, тесла-башня, зенитка. Тесла-башня зависит от энергии.
8. Туман войны на уровне симуляции (для каждого игрока) и в клиенте (шейдер, скрытые враги, «призраки» зданий).
9. Обратная связь в клиенте: полоски здоровья, курсор атаки, эффекты-заглушки выстрелов, попаданий и взрывов.
10. Все боевые юниты Союза из MVP настроены в YAML и воюют.

**Как это выглядит для игрока:** две базы Союза на тестовой карте. Игрок (переключаясь отладочной клавишей между игроками 0 и 1) собирает танки и пехоту, отправляет атака-движением в туман, видит, как армии сходятся, тесла-башня бьёт молниями, здания горят и рушатся.

## 4. Технические решения

### 4.1. Модель боя

Цепочка, как в RA2:

```
Юнит ──► Оружие (WeaponDefinition) ──► Снаряд (ProjectileDefinition) ──► Боеголовка (WarheadDefinition)
              │                                                              │
              └─ урон, дальность, перезарядка                                └─ Verses по броне, площадь, эффекты
```

- **Оружие** знает, *сколько* и *как часто*.
- **Снаряд** знает, *как долетает*.
- **Боеголовка** знает, *по чему и как сильно*.

Одна боеголовка переиспользуется многими видами оружия — баланс правится в одном месте.

### 4.2. Типы брони

Порядок фиксирован в `armor.yaml` — по нему индексируются таблицы Verses:

| Индекс | Броня | Кто носит |
|---|---|---|
| 0 | `none` | Пехота |
| 1 | `flak` | Лёгкая пехота с бронежилетом |
| 2 | `plate` | Тяжёлая пехота |
| 3 | `light` | Лёгкая техника |
| 4 | `medium` | Средняя техника, харвестер |
| 5 | `heavy` | Тяжёлые танки |
| 6 | `wood` | Лёгкие здания |
| 7 | `steel` | Обычные здания |
| 8 | `concrete` | Укреплённые здания, оборона |
| 9 | `special_1` | Особые случаи (зарезервировано) |
| 10 | `special_2` | Особые случаи (зарезервировано) |

### 4.3. Форматы данных

**Боеголовка:**

```yaml
warheads:
  ap_shell:                   # бронебойный снаряд танка
    verses: [25, 25, 25, 75, 100, 100, 50, 50, 40, 100, 100]   # % по индексам брони
    spread: 0.5               # радиус площади в клетках (0 = только цель)
    percentAtMax: 50          # % урона на краю радиуса
    wallDamage: true
    affectsAir: false
    infantryDeath: explode    # анимация смерти пехоты (для клиента)
```

**Снаряд:**

```yaml
projectiles:
  bullet:   { kind: instant }
  shell:    { kind: ballistic, speed: 40, arc: 2, inaccuracy: 0.25 }   # скорость — лептоны/тик, разброс — клетки
  rocket:   { kind: homing,    speed: 30, rot: 16, maxLifetime: 90 }   # rot — бинарные градусы/тик
  tesla:    { kind: instant, visual: electric_bolt }
```

**Оружие:**

```yaml
weapons:
  heavy_tank_cannon:
    damage: 90
    rof: 50                   # тиков между выстрелами
    range: 5.75               # клеток
    minRange: 0
    projectile: shell
    warhead: ap_shell
    burst: 2                  # выстрелов в очереди
    burstDelay: 3             # тиков между ними
    targets: [ground]         # ground | air
    report: snd_tank_cannon   # звук выстрела (клиент)
```

**Юнит / здание** получают поля:

```yaml
  heavy_tank:
    hp: 400
    armor: heavy
    sight: 6                  # клеток
    primary: heavy_tank_cannon
    secondary: null
    turret: { rot: 24 }       # скорость поворота башни; нет поля — стреляет корпусом
    crusher: true
    crushable: false
    threatPosed: 30           # насколько опасен — для приоритетов целей
    defaultStance: aggressive
```

**Дробные числа** (`5.75`, `0.25`) читаются через детерминированный разбор десятичной записи в `Fixed`, как в M3. Клетки переводятся в лептоны при загрузке.

**Проверка данных при загрузке:** все ссылки (оружие → снаряд, боеголовка; юнит → оружие) существуют, длина `verses` равна числу типов брони, проценты в 0–1000. Ошибка — понятное сообщение с файлом и ключом.

**Как сделано (шаг 1).** Формат — по правилам данных M3 ([formats/data.md](../formats/data.md)), а не по черновику выше:
- **Записи с `kind`**, а не группы `warheads:` / `projectiles:` / `weapons:`; новые виды `armor`, `warhead`, `projectile`; ключи snake_case (`percent_at_max`, `min_range`, `burst_delay`, `infantry_death`); время — в секундах (`reload: 4.33s` → 65 тиков: RA2 `ROF` / 15, тик — кадр RA2). Id уникален во всех видах, поэтому снаряд флака — `flak_shell` (броня `flak` занята).
- **Броня** — записи `kind: armor`; её номер — место по `id` (`RulesDatabase.IndexOfArmor`), порядок в файле не важен.
- **`verses` — словарь по имени брони** (решение владельца): `{ none: 25%, …, heavy: 100% }`. Проверка требует долю по каждой броне, знает только существующую броню, проценты 0–1000 %; ошибка — на имени брони внутри словаря.
- **У снаряда вид движения — `motion`** (`instant` / `ballistic` / `homing`): `kind` занят видом записи. Летящему нужна `speed`, самонаводящемуся ещё `turn_rate` и `lifetime`.
- **Оружие юнита — `primary` / `secondary`** (решение владельца; список `weapons` M3 убран), у здания — `armor` и `primary`. `secondary` без `primary` — ошибка; броня у каждого юнита и здания обязательна (шаблоны дают её по умолчанию: пехота `none`, техника `heavy`, здания `wood`, оборона `steel`).
- **`targets`** — список из `ground` и `air`, по умолчанию `[ground]`; `burst` по умолчанию 1.
- Ключи давки, режимов, угрозы и башни (`crusher`, `stance`, `threat`, скорость башни) придут со своими шагами (8, 7, 6, 3).
- Звук выстрела (`report`), смерть пехоты (`infantry_death`) и вид снаряда (`visual`) — для клиента: в хеш данных не входят.

### 4.4. Здоровье и состояния повреждений

| Состояние | Порог | Для чего |
|---|---|---|
| Целый | > 50% | Зелёная полоска |
| Повреждён | 25–50% | Жёлтая полоска; у зданий — дым |
| Сильно повреждён | < 25% | Красная полоска; у зданий — огонь, у части зданий — снижение эффективности (решаем в балансе) |
| Уничтожен | 0 | Гибель |

- `Health` хранит `int Current`, `int Max`. Без `Fixed` — урон всегда целый.
- Смена состояния порождает событие `DamageStateChanged` — клиент меняет визуал.

### 4.5. Формула урона

```
базовый   = weapon.damage
по броне  = базовый × verses[броня_цели] / 100
на дистанции d от центра взрыва (spread > 0):
    спад  = 100 − (100 − percentAtMax) × d / spread         (d ≤ spread, иначе 0)
итог      = по броне × спад / 100
если verses > 0 и цель прямая — итог не меньше 1
```

- Всё в целых числах и `Fixed`, расстояние — `Fixed.Sqrt` от квадрата разности в лептонах.
- Порядок округления фиксирован: каждое деление — вниз для неотрицательных значений.
- Дружественный огонь по площади **включён**, как в RA2 (по своим юнитам в радиусе), кроме прямой цели-союзника без принудительной атаки.

**Как сделано (шаг 2).**
- **Прочность юнитов:** `Unit.Hp` (в хеше, `SimulationVersion` 26) и `MaxHp` из `UnitArchetype.Hp`; у архетипа — номер брони `Armor`. Отдельного компонента `Health` нет: у зданий и объектов карты прочность уже была полями, юниты сделаны так же. Здания меняют прочность одним путём — `GameWorld.SetHp` (урон по K, ремонт).
- **Состояния** — `Combat/DamageStates.Of(hp, max)` в целых числах: `hp × 2 > max` — целый, `hp × 4 < max` — критический, 0 — уничтожен; ровно половина — уже «повреждён», ровно четверть — ещё «повреждён». Событие `DamageStateChanged` — при пересечении порога вниз и вверх (ремонт), уничтожение сообщает своё событие (шаг 9).
- **Формула** — `Combat/DamageCalculator`: `AgainstArmor` (урон × доля, вниз), `FallOff` (радиус площади — `spread` × 256 лептонов, вниз; дальше радиуса и при нулевой площади — 0), `Direct` (цель попадания: вся доля по броне, не меньше 1, если доля больше нуля), `InArea` (прочие в площади: доля по броне, затем спад, без минимума), `Distance` (целочисленный корень в лептонах). Отличие от черновика: цель попадания получает всю долю без спада — спад считается для остальных в площади; где упадёт неточный снаряд, решит шаг 4.
- **Доли по номеру брони** — `GameRules.Verses(боеголовка, броня)` и `GameRules.ArmorOfBuilding`: раскладываются при сборке правил, по ходу боя строки не ищутся.

### 4.6. Башни и наведение

- Юнит с `turret` поворачивает башню к цели со скоростью `rot`, корпус — независимо (едет куда угодно).
- Без башни юнит поворачивает корпус (скорость поворота из M2).
- **Стрельба разрешена**, когда разница между углом оружия и направлением на цель ≤ допуска (по умолчанию 8 бинарных градусов из 256 на круг; хранится 16-битно, как в M2).
- Направление на цель — детерминированная таблица `atan2` из M2.

### 4.7. Стрельба (`WeaponSystem`)

На каждом тике для каждой сущности с оружием (по возрастанию ID):

```
1. Есть цель? Она жива, видима владельцу (или принудительная атака по земле)?
2. В дальности [minRange, range]? Нет — движение к цели (если режим позволяет)
3. Наведение башни/корпуса завершено?
4. Перезарядка = 0? → выстрел: создать снаряд(ы), событие WeaponFired,
   перезарядка = rof, очередь burst с интервалом burstDelay
```

Перезарядка тикает всегда, даже без цели (как в RA2 — нельзя «накопить» выстрел).

**Как сделано (шаг 3).**
- **Состояние:** у юнита и обороны — `Target` (id сущности) и `Weapons` — `WeaponInstance` на слот (основное, второе): `ReloadLeft`, `BurstLeft`, `BurstDelayLeft`. Всё в хеше (`SimulationVersion` 27). Номера оружия — у архетипа юнита (`Primary`, `Secondary`) и у правил для зданий (`GameRules.WeaponOfBuilding`). Отдельного класса `Turret` нет: угол башни — прежний `Unit.TurretFacing`, скорость — новый ключ данных `turret_turn_rate` (по умолчанию как у корпуса).
- **`Systems/WeaponSystem`** — после ремонта, до движения. Перезарядка и пауза очереди убывают каждый тик; без цели или с погибшей целью очередь сбрасывается, а башня возвращается к корпусу. Оружие — первое из основного и второго, которое бьёт землю и достаёт цель (расстояние — до юнита или до ближайшей точки пятна здания; от обороны — из центра её пятна). Наведение: башня — со своей скоростью; юнит без башни доворачивает корпус, только пока стоит; пехота (`turn_rate` 0) и оборона — сразу. Стрельба — при расхождении не больше 2048 BAngle (8/256 круга) и готовности: первый выстрел очереди ставит перезарядку, следующие — через `burst_delay`. Выстрел пока — событие `WeaponFired` (снаряд и урон — шаги 4–5).
- **Движение** больше не тянет башню за корпусом у юнита с целью: башня держит цель, пока корпус едет.
- Цель задаётся прямо (тесты); приказ «атаковать» — шаг 7, выбор целей — шаг 6. Энергия обороны — шаг 10.

### 4.8. Снаряды

Снаряд — **сущность симуляции** (`Projectile`) с ID из общего счётчика: владелец, оружие, позиция, цель (ID или точка), оставшееся время жизни.

| Класс | Поведение | Попадание |
|---|---|---|
| `instant` | Не создаёт сущность, урон применяется на этом же тике | Точно в цель |
| `ballistic` | Летит прямо к **точке**, где была цель в момент выстрела, + разброс | В точку прибытия; урон по площади вокруг |
| `homing` | Каждый тик поворачивает к **текущей** позиции цели не более чем на `rot` | При сближении ≤ 64 лептонов или по истечении `maxLifetime` |

- **Разброс** (`inaccuracy`): смещение точки прицеливания — случайный угол и случайное расстояние до `inaccuracy`, через `DeterministicRandom` симуляции. Порядок вызовов ГСЧ фиксирован порядком обхода снарядов по ID.
- **Время полёта** баллистики = расстояние / скорость (округление вверх). Дуга — только визуальная: высота считается в клиенте по доле пройденного пути.
- Цель погибла до попадания: `ballistic` прилетает в точку, `homing` летит в последнюю известную позицию.

**Как сделано (шаг 4).**
- **Сущность `World/Projectile`** — id из общего счётчика (`GameWorld.Launch`), в хеше (`SimulationVersion` 28): стрелок, оружие, цель, откуда, где сейчас, точка прицела, последняя точка цели, курс, время полёта, сколько тиков осталось, тик пуска.
- **Пуск — в `WeaponSystem`**, но после обхода сущностей: выстрелы тика собираются в список и запускаются потом (менять список сущностей во время обхода нельзя). Мгновенный выстрел сущности не создаёт: попадание в тот же тик, в ближайшую точку цели. Баллистический летит в ближайшую точку цели, смещённую на случайный угол и случайное расстояние до `inaccuracy` (`world.Random`, в порядке стрелков по id); время полёта — расстояние / скорость вверх, не меньше 1 тика; позиция — по прямой, по доле пройденного. Самонаводящийся берёт курс на цель и `lifetime` тиков жизни.
- **`Systems/ProjectileSystem`** — после `WeaponSystem`, до движения; снаряд, пущенный на тике, летит со следующего (попадание на тике `пуск + время полёта`). Баллистический падает в свою точку, жива цель или нет. Самонаводящийся поворачивает к цели не больше `turn_rate` за тик, делает шаг `speed`, помнит последнюю точку живой цели и после её гибели летит туда; попадает в пределах 64 лептонов, а по истечении жизни падает где летит без цели. Снаряд после попадания помечен мёртвым и убран в конце тика.
- **Событие `ProjectileImpact`** — снаряд (у мгновенного нет), стрелок, оружие, точка, живая цель или пусто. Урон по нему — шаг 5. Дуга баллистики — только визуальная, в клиенте (шаг 13).
- **Данные:** у ракеты `turn_rate` 8192 (45° за тик) вместо 2048 — при 2048 радиус её поворота (≈150 лептонов) больше радиуса попадания (64), и на пересекающемся курсе ракета могла бы кружить вокруг цели.

### 4.9. Применение урона (`DamageSystem`)

Урон **не применяется в момент попадания**, а собирается в буфер тика:

```
1. Все попадания тика собираются как (источник, цель/точка, боеголовка, урон)
2. Буфер сортируется по (ID снаряда или стрелка, порядковый номер)
3. Применяется по порядку: для площади — запрос к пространственному хешу,
   цели в радиусе сортируются по ID
4. Здоровье ≤ 0 → отметка «мёртв», событие EntityDestroyed (причина, убийца)
5. Мёртвые удаляются на шаге очистки тика (из M0)
```

Так результат не зависит от того, в каком порядке системы нашли попадания. Мёртвые на этом тике ещё могут получить урон, но не стреляют.

### 4.10. Выбор цели (`TargetingSystem`)

- Запускается для каждой сущности **раз в 4 тика**, со сдвигом по `ID % 4` — нагрузка размазывается равномерно, результат детерминирован.
- Кандидаты: враги в радиусе `max(range, sight)` из пространственного хеша, **видимые владельцу** (см. 4.14).
- Оценка кандидата (целое число, больше — лучше):

```
очки = threatPosed_цели × 10
     + (цель уже атакует меня ? 50 : 0)
     + (verses моего оружия по броне цели) / 2      — предпочитаем тех, кого бьём эффективно
     − расстояние_в_клетках × 5
     + (это текущая цель ? 20 : 0)                  — инерция, чтобы не дёргаться
```

- Равные очки → меньший ID. Никаких случайностей.
- Оружие с `targets: [air]` не рассматривает наземные цели и наоборот.
- Здания-оборона ищут цели так же, но не двигаются.
- Безоружные (инженер, MCV) не ищут цели. Харвестер с пулемётом — ищет, но только в радиусе оружия и не отъезжает.

### 4.11. Режимы поведения

| Режим | Ищет цели | Преследует | Возврат |
|---|---|---|---|
| **Агрессивный** (по умолчанию) | В радиусе обзора | Да, пока цель видна | Нет |
| **Охрана** | В радиусе обзора | До 6 клеток от точки охраны | Возвращается на точку |
| **Удерживать позицию** | В радиусе оружия | Нет | — |

Хранится в сущности, меняется командой `SetStanceCommand`.

### 4.12. Команды

| Команда | Параметры | Поведение |
|---|---|---|
| `AttackCommand` | юниты, ID цели | Атаковать только эту цель, преследовать, пока видна. После гибели — вернуться к автоматическому выбору |
| `ForceAttackCommand` | юниты, ID цели **или** точка | Атаковать что угодно, включая свои юниты, здания и землю (Ctrl+клик) |
| `MoveUnitsCommand` (из M0/M2) | — | Обычное движение **игнорирует** врагов по пути до прибытия (как в RA2) |
| `AttackMoveCommand` (из M2, теперь настоящий) | юниты, точка | Двигаться, атакуя всё по пути; после уничтожения — продолжить к точке |
| `StopCommand` (из M2) | юниты | Сброс приказов и цели |
| `SetStanceCommand` | юниты, режим | Сменить режим |

Все команды проверяются по правилам M0: юниты принадлежат игроку, цель существует. **Нельзя атаковать то, чего игрок не видит** — команда на невидимую цель отбрасывается (защита от мапхака на уровне приказов).

### 4.13. Давка пехоты (`CrushSystem`)

- Техника с `crusher: true` при въезде в клетку проверяет пехоту с `crushable: true` в подклетках (подклетки — из M2).
- Давит **не союзную** пехоту. Своих и союзников — объезжает (это задача поиска пути M2: подклетки со своей пехотой считаются временно занятыми, пехота отходит).
- Раздавленный — мгновенная гибель, событие `EntityDestroyed` с причиной `crushed`.
- Пехота, которую «целит» танк, не убегает автоматически — это уже микро игрока (как в RA2).

### 4.14. Туман войны в симуляции

**Два состояния на клетку для каждого игрока:**

| Состояние | Значение | Хранение |
|---|---|---|
| **Завеса (shroud)** | Клетку никогда не видели — полностью чёрная | Бит «разведано» |
| **Туман (fog)** | Видели раньше, но сейчас не видно — видны только рельеф и последние известные здания | Разведано, но счётчик видимости = 0 |
| **Видно** | Сейчас видно | Счётчик видимости > 0 |

**`VisibilityGrid`** на игрока: массив `ushort` (сколько источников видят клетку) + битовый массив «разведано». Для карты 64×64 — ≈ 8,5 КБ на игрока; для 200×200 — ≈ 85 КБ.

**Инкрементальное обновление:**
- `SightCircles` — заранее рассчитанные списки смещений клеток для каждого радиуса обзора (целочисленная проверка `dx² + dy² ≤ r²`, это `SightRules.InSight` из M7).
- Радиус обзора юнита — `SightRules.SightOf` (M7, шаг 8): базовый обзор типа плюс бонус высоты клетки; поэтому круг пересчитывается при каждой смене клетки, и на холме он больше.
- Когда сущность **меняет клетку**: вычесть круг со старой клетки, добавить с новой. Если клетка не менялась — ничего не делаем.
- Появление сущности — добавить круг, гибель — вычесть.
- Союзники делят видимость: при запросе «видит ли игрок P» проверяются сетки P и его союзников (команды из настроек партии).
- Здания дают обзор, как юниты.

**Где используется видимость в симуляции:**
- выбор целей — только видимые враги;
- проверка команд атаки;
- бот (M5) — через «вид глазами игрока».

**Хеш:** сетки видимости входят в контрольную сумму раз в 15 тиков (дешевле, чем каждый тик, и всё равно ловит расхождение быстро).

### 4.15. Туман войны в клиенте

- **Текстура тумана:** `Image` размером с карту (1 пиксель = 1 клетка), канал R: 0 — завеса, 128 — туман, 255 — видно. Обновляется только изменившимися клетками (симуляция отдаёт список изменённых клеток для локального игрока за тик).
- **Шейдер** на земле и объектах: затемнение и десатурация по текстуре с билинейной фильтрацией — края плавные. Отдельный проход для чёрной завесы с мягкой границей.
- **Сглаживание во времени:** значение в текстуре плавно догоняет целевое за ~0,25 с — туман «открывается», а не щёлкает.
- **Скрытые враги:** вражеские юниты в невидимых клетках не рисуются и не выделяются.
- **«Призраки» зданий:** клиент запоминает последнее увиденное состояние вражеских зданий (тип, позиция, повреждение). В тумане рисуется призрак, пока клетку снова не увидят. Это только визуал, симуляцию не затрагивает.
- Отладочная клавиша: показать всю карту (без влияния на симуляцию).

### 4.16. Гибель и разрушение (`DeathSystem`)

**Юнит:**
- событие `EntityDestroyed` (тип смерти по боеголовке: взрыв, сожжён, электричество, раздавлен);
- освобождает клетку / подклетку, вычитает обзор, сбрасывается из групп и выделения (клиент — по событию);
- харвестер: груз пропадает.

**Здание:**
- событие `EntityDestroyed` + визуальные обломки (воронка, мусор — клиентский декаль, без коллизий);
- клетки освобождаются **на следующем тике** (чтобы никто не успел встать в клетку в тот же тик);
- фабрика: очередь производства отменяется, деньги за недостроенное возвращаются (как в RA2);
- электростанция: пересчёт энергии;
- стройплощадка: строительство зданий становится недоступным (по правилам M3).

**Выжившие из зданий** (пехота, выбегающая из разрушенного) — M11.

### 4.20. Клиент: полоски здоровья и курсоры

- **Полоски здоровья:** рисуются одним батчем (MultiMesh или собственный `_Draw` в экранном пространстве) — сотни полосок без потерь FPS. Стиль RA2: «квадратики» (pips), цвет по состоянию.
- Показываются у выделенных и повреждённых (настройка: всегда / выделенные / повреждённые).
- **Курсоры:** движение, атака (над видимым врагом), принудительная атака (Ctrl), нельзя.
- **Отладочное переключение игрока:** F2 — управлять следующим игроком (только в отладочной сборке). Нужен, пока нет бота.

## 6. Тесты

### Модульные

| Область | Что проверяем |
|---|---|
| `DamageCalculator` | Verses по каждой броне; спад на центре, на краю, за краем; минимум 1; нулевой Verses даёт 0 |
| `WeaponInstance` | Перезарядка; очередь `burst` с `burstDelay`; перезарядка тикает без цели |
| `Turret` | Поворот с ограничением скорости; стрельба только при наведении в допуске |
| Снаряды | Время полёта баллистики; самонаводящийся догоняет движущуюся цель; разброс в пределах радиуса; погибшая цель |
| `DamageSystem` | Порядок применения; урон по площади своим; мёртвые не стреляют |
| `TargetingSystem` | Приоритет угрозы; эффективность против брони; инерция; ID при равенстве; только видимые цели; воздух/земля |
| Режимы | Агрессивный преследует; охрана возвращается; удержание не двигается |
| `CrushSystem` | Давит врага; не давит союзника; не давит, если `crushable: false` |
| `DeathSystem` | Освобождение клеток на следующем тике; отмена очереди фабрики; пересчёт энергии |
| `VisibilitySystem` | Инкрементальное обновление совпадает с полным пересчётом после 1000 случайных перемещений; завеса не возвращается; союзники делят видимость |
| Загрузчик данных | Ошибки в ссылках, длине `verses`, диапазонах |

### Сценарные (симуляция без клиента)

| Сценарий | Ожидание |
|---|---|
| 5 тяжёлых танков против 5 тяжёлых танков | Заканчивается за разумное число тиков, есть победитель, результат одинаков в двух прогонах |
| 10 призывников против 1 тяжёлого танка | Танк побеждает (давка + пушка) |
| 3 ракетчика против 1 тяжёлого танка | Ракетчики побеждают |
| Тесла-башня против 4 тяжёлых танков (с энергией / без) | С энергией башня наносит заметный урон; без — ноль |
| Атака-движение через поле врагов | Юниты останавливаются, уничтожают, продолжают к точке |
| Тестовая воздушная цель над зенитной машиной | Зенитка стреляет, наземная пехота — нет |

### Детерминизм

- Бой 300 на 300 юнитов, 3000 тиков: два прогона — одинаковые суммы на каждом тике.
- Тот же бой через повтор: запись → чтение → проигрывание — суммы совпадают.
- Обновление «золотой» контрольной суммы эталонного сценария (новые поля состояния: здоровье, оружие, снаряды, видимость) — в том же коммите, с объяснением.

### Защита хеша

Тест из M0 (через рефлексию) расширяется на новые компоненты: `Health`, `WeaponInstance`, `Turret`, `Projectile`, `VisibilityGrid`, режим поведения, текущая цель.

## 8. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Производительность выбора целей при сотнях юнитов | Средняя | Распределение по тикам, пространственный хеш, кэш кандидатов; профилирование на шаге 15 |
| Расхождение из-за порядка применения урона | Средняя | Буфер урона с сортировкой (4.9), тест перестановки систем |
| Баланс «сломан» с первой попытки | Высокая | Это нормально: стартуем с пропорций RA2, баланс v0 проверяем сценариями, полноценно — в M8 через бот-против-бота |
| Туман в клиенте выглядит «квадратно» | Средняя | Билинейная фильтрация, сглаживание во времени, отдельный проход для завесы |
| Нагрузка от обновления видимости | Низкая | Только при смене клетки; круги заранее посчитаны |
| Проверка зениток без авиации | Низкая | Тестовая воздушная цель в тестах и отладочном спавне |
