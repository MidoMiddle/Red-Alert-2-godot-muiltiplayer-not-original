# Модели элементов карт: что делает Haiku 5.5, а что Opus 5.5

> Статус: черновик · Создан: 2026-10-28
> Связанные документы: [производство элементов](production_plan.md) · [модели зданий](../ra2_buildings/model_work_split.md) · [модели юнитов](../art/unit_models_plan.md) · [требования к моделям](generation_requirements.md) · [реестр ассетов](../assets_registry.md)

Кто из двух моделей делает каждый из 115 элементов карт из [производства элементов](production_plan.md). Правило то же, что у [зданий](../ra2_buildings/model_work_split.md) и [юнитов](../art/unit_models_plan.md). Здесь добавлен случай, которого у них нет: элемент, где модель делает Haiku, а код к ней пишет Opus.

**Это оценка до пробы.** На моделях проекта Haiku 5.5 ещё не пробовали. Разделение ниже — исходное. Первые модели покажут, где граница на деле; по ним документ поправим.

---

## 1. Правило

- **Opus делает первый образец.** Первый элемент нового семейства, первая подвижная часть (ворота, стрела крана, вращение), живая форма (люди, животные, корпус корабля). Его скрипт становится образцом для остальных.
- **Haiku повторяет по образцу.** Если похожий скрипт уже есть в `tools/blender/families/` или `tools/blender/units/`, Haiku копирует его и меняет размеры и детали.
- **Haiku делает простое с нуля.** Коробки, цилиндры, плиты. Без подвижных частей и без геометрии разрушения.
- **Механика и код — Opus.** Всё, что меняет движок или симуляцию: вода, шейдеры, туман, свет, цикл светофора, рост руды, мины, гарнизоны, захват, ломка льда.
- **Смешанный элемент.** Haiku делает модель или текстуру, Opus — код. Сначала модель: код опирается на её узлы.
- **Каждую модель Haiku смотрит Opus или владелец** по снимку (раздел 4 [моделей зданий](../ra2_buildings/model_work_split.md)). После двух неудач модель переходит к Opus.
- **Готово** — элемент в игре или в реестре, и ничего не осталось.

## 2. Виды работы

| Работа | Кто | Почему |
|---|---|---|
| Простая форма из коробок, цилиндров и плит по размерам из `appearance.md` | Haiku | геометрия однозначна |
| Копия скрипта семейства под новый элемент | Haiku | структура уже есть |
| Текстура земли или декали: CC0-библиотека, PNG, материал в `look.yaml` | Haiku | по шаблону; загрузка файлов — с разрешения владельца |
| Генератор (Г): промт, запуск, нормализация по чек-листу | Haiku | промт и сервис заданы |
| Строка в `game/data/visuals/models.yaml`, запись в `docs/assets_registry.md` | Haiku | по образцу соседних строк |
| Первая модель семейства, новый тип узлов | Opus | задаёт образец |
| Геометрия разрушения: пролом, обрушение, руины | Opus | своя геометрия, как в `civil_house.py` |
| Подвижная часть: ворота, стрела крана, вращение (первая) | Opus | ось и иерархия узлов должны совпасть со стандартом |
| Живые формы: люди, животные, первый корпус корабля | Opus | не собираются из коробок |
| Mixamo (М): ретаргет и скелет в Godot | Opus | техника движка |
| Код движка и симуляции (Д): шейдер, вода, туман, свет, цикл, рост руды | Opus | детерминизм и тесты симуляции |
| Инструменты W0 и тест генераторов W2 | Opus | задают критерии для всех остальных |

## 3. Элементы по наборам

Колонка «Кто» относится к работе, которая ещё не сделана. Колонка «Почему» пишет, что уже есть и что осталось.

- **Haiku** — с нуля, простая форма или текстура;
- **Haiku по образцу** — копия скрипта из колонки «Образец»;
- **Haiku + код Opus** — модель или текстуру делает Haiku, код подключает Opus;
- **Opus** — первый образец, механика, код или сложная форма;
- **готово** — ничего не осталось.

## 5. Пограничные случаи

- **Haiku, но силуэт смотрит Opus.** Ориентиры, которые узнают по контуру: церковь (город 05), маяк (пляж 12), небоскрёб (город 19), водонапорная башня (умеренный 07). Если снимок не проходит, модель переходит к Opus.
- **Фасады с рядами окон.** Школа, офис, гостиница, банк: по образцу `civil_block.py`. Ряды и проёмы проверяет глаз, скрипт этого не покажет.
- **Первый корпус Opus, дальше Haiku.** Лодка на песке (пляж 17) и гражданские суда (флот 08). Следующие корпуса — Haiku по образцу первого.
- **Высокий мост** (карта 05). Правила и разрушение — Opus. Опоры и балки — Haiku по образцу `bridge.py`, когда правила готовы.
- **Руины** (пустыня 08). Геометрия разрушения — Opus. Когда появится первый образец, следующие руины — Haiku по нему.
- **Дубли.** Городской дом и многоэтажка (город 01–02) повторяют ассеты карты 11. Один ассет или два решает владелец ([производство элементов](production_plan.md), раздел 8).

## 6. Как ставить задачу

- Задача начинается с исполнителя: «Haiku» или «Opus», затем номер и название элемента из раздела 3.
- **Для Haiku** в задании: папка элемента, образец (скрипт или ассет), `appearance.md` и `prompts.md` элемента, список файлов, чек-лист готовности ([производство элементов](production_plan.md), раздел 3.6), «не коммитить».
- **Для Opus** в задании: цель, границы (что не трогать), тесты и что проверить глазами.
- **Смешанный элемент** — две задачи подряд: сначала модель (Haiku), потом код (Opus).
- **Запуск** — как у зданий: отдельная сессия или субагент из сессии Opus ([модели зданий](../ra2_buildings/model_work_split.md), раздел 5).

## 7. Открытые вопросы

1. **Пилот.** Первыми Haiku делает скамейку (город 10) и колодец (умеренный 06) с нуля и фермерский дом (умеренный 08) по образцу. Opus смотрит снимки. Если все три проходят, остальные Haiku-элементы идут в работу.
2. **Дубли.** Городские дома (город 01–02): один ассет с картой 11 или два ([производство элементов](production_plan.md), раздел 8).
3. **Декор.** Город 09–13, 15, 16, 20, 21 и куст (карта 09): делать ли их, решает владелец до назначения исполнителя ([производство элементов](production_plan.md), раздел 9, пункт 6).
