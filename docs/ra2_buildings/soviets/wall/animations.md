## Постройка

- **Оригинал:** по ModEnc (Wall, ToOverlay) здание с `Wall=yes` при создании превращается в оверлей (накладку на клетку), а `NAWALL` значится в списке оверлеев как «Soviet Wall» (OverlayTypes); README указывает `Wall=yes` и имя `NAWALL`. Есть ли у стены анимация постройки (ключ `Buildup`, ModEnc), сколько в ней кадров и стадий — (не подтверждено); appearance: анимация постройки не описана. Ставится протяжкой: cncnz пишет о 4 сегментах за раз рядом с существующей стеной, промежуток заполняется сам (appearance, не сверено).
- **Время:** ≈0:04 на сегмент и `WallBuildSpeedCoefficient=3.0` (ModEnc: ключ ускоряет или замедляет постройку стен относительно других зданий) — по README, не сверено в игре. По обзору зданий здание сначала строится в очереди сайдбара и только потом ставится на карту, поэтому ≈0:04 — не обязательно длительность видимого проявления (вывод, не сверено). Предложение: `build_up` на каждый сегмент, при протяжке по очереди вдоль линии; длительность на карте подобрать в прототипе.

## Простой

Анимация в покое в источниках не описана (не подтверждено): appearance даёт только «вид не описан; в галерее есть SHP-спрайт» (C&C Wiki, не проверено), а README стену статичной прямо не называет, поэтому «анимации нет» не утверждаю. ModEnc описывает ActiveAnim и IdleAnim как анимации зданий; для стены-оверлея они не подтверждены. Предложение: статичная модель; чтобы линия оставалась сплошной (appearance), нужны варианты сегмента по соседям (предложение).

## Действия

Действий нет: стена пассивна — cncnz называет её пассивной обороной, README указывает вооружение «нет», appearance — при работе и при атаке анимаций нет. Подразделы не нужны. Реакция на попадание (вспышка, искры) в источниках не описана (не подтверждено), не добавляю.

## Без энергии

Как в простое: энергия 0, стена её не требует (README, не сверено в игре; cncnz: Power 0; appearance: «как в покое»). Отдельной анимации не нужно (вывод из README).

## Повреждение и разрушение

- **До ~50% HP:** вид не описан (appearance: отдельный вид не подтверждён); ремонта нет (`Repairable=false`), перестроить поверх можно (README, не сверено в игре). ModEnc: у оверлея-стены нет обычных очков здоровья (README при этом указывает 300 HP): попадание с некоторой вероятностью снимает «слой» (Strength), а число ступеней с целой задаёт DamageLevels; для `NAWALL` оно не подтверждено, так что привязка ступеней к ~50% и ~25% HP — предложение. Огонь и дым (ConditionYellow) ModEnc описывает для зданий, у стены не подтверждены. Предложение: смена меша на вариант с трещинами и лёгкая пыль в `damage_*`, без огня.
- **До ~25% HP:** вид не описан (не подтверждено); порог ~25% проектный, не подтверждён ModEnc (ConditionRed пишет 50%). Предложение: следующая ступень перед разрушением — меш с крупными трещинами и выкрошенным бетоном, пыли чуть больше, огня нет.
- **Разрушение:** вид не описан (appearance; не подтверждено). По ModEnc число выстрелов до разрушения стены зависит от DamageLevels (Strength); боеголовка с `WallAbsoluteDestroyer` (ядерная — по README) сносит её сразу, минуя ступени (Wall); повреждённая стена наносит 200 урона другим стенам в радиусе 4 клеток, поэтому соседи могут рушиться цепочкой (общий механизм, для `NAWALL` не сверено; в README этого нет). Предложение: обломки бетона и пыль (`debris_*`) без взрыва, никто не выбегает; соседние сегменты пересчитывают вариант (торец вместо линии).

## Продажа и захват

- **Продажа:** (не подтверждено). README: обычно не продаются (не выделяются), точное поведение не подтверждено; ModEnc (Buildup): без ключа `Buildup` здание продать нельзя — есть ли он у стены, не подтверждено; как проигрывается продажа, источники не говорят. Предложение: если продажу разрешим, то обратный `build_up`.
- **Захват:** не захватывается (`Capturable` нет — по README, не сверено в игре). Цвета владельца у стены нет (appearance), так что смена владельца ничего не меняет; перекраска не нужна (предложение).

## Для нашей версии

- Из соглашений проекта стене нужны `build_up` на сегмент и `debris_*` при разрушении, плюс меши ступеней повреждения и варианты по соседям (всё — предложение); `damage_*` — не более лёгкой пыли (предложение). `spin_*`, `smoke_*`, `light_*` и клипы `open`/`close`/`active` не нужны: действий у стены нет (README, cncnz).
- Проверить в прототипе: 1) сколько ступеней повреждения нужно (DamageLevels у `NAWALL` не подтверждён) и читаются ли они с игровой камеры; 2) нагрузку от сотен сегментов с пылью и обломками (общий эмиттер или MultiMesh — предложение); 3) протяжку: сегменты появляются разом или по очереди и хватает ли им времени `build_up`.
