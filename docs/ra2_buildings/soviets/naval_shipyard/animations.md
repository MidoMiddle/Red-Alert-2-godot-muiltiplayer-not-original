## Постройка

Анимацию постройки задаёт ключ `Buildup` (ModEnc; без него здание нельзя продать). В галерее C&C Wiki есть анимация Buildup (по appearance, вики сейчас недоступна), но вид, число кадров и стадий не описаны (не подтверждено). Время постройки ≈0:40 (по README, не сверено в игре; совпадает ли оно с длительностью анимации, не подтверждено). В YR 1.001 точку сбора можно ставить уже во время этой анимации (README). Для нас: шейдер `build_up` снизу вверх, прогресс из стадии постройки (соглашение M1, 4.13).

## Простой

В покое анимация не подтверждена: appearance помечает покой «не подтверждено», README о нём молчит. Кран и док названы в README (не сверено в игре), движутся ли они в покое, не подтверждено. ModEnc (`IdleAnim`) называет сервисное депо и строительную площадку, верфь не названа (не подтверждено). Предложение: статика, модель стоит в позе «закрыто» (исходная поза клипа `open`).

## Действия

### Производство и выход кораблей

- **Запуск:** из очереди готов корабль (README: верфь выпускает весь флот Советов). По ModEnc (`Naval`) верфь — такой же завод техники, как военный завод, но с флагом `Naval=yes`: он отличает морской завод от наземного и разрешает ставить здание только на воду.
- **Что движется или светится:** не описано (appearance: выход кораблей не описан). ModEnc описывает `ProductionAnim` (раз на созданного юнита) и спрайты выхода техники (`DeployingAnim`, `UnderDoorAnim`) для заводов с `WeaponsFactory=yes`; README у верфи этого флага не называет, поэтому для неё не подтверждено.
- **Длительность и цикл:** по событию, однократно на каждый корабль (предложение); в оригинале длительность и число кадров не подтверждены.
- **Для нашей модели:** отдельный клип не нужен (предложение); точку появления корабля на воде задаёт логика, а не модель (предложение). Если сверка в игре покажет движение крана или створок, добавим клип (предложение).

### Ремонт кораблей в доке

- **Запуск:** корабль встал в док (README: `UnitRepair=yes`, один док; ремонт платный, без денег останавливается). По ModEnc (`UnitRepair`) флаг даёт стыковку и ремонт, темп и цену задают `URepairRate` и `RepairStep`.
- **Что движется или светится:** подтверждено ModEnc, который прямо называет морскую верфь: [`SpecialAnim`](https://modenc.renegadeprojects.com/SpecialAnim) — первая стадия анимации ремонта кораблей, [`SpecialAnimTwo`](https://modenc.renegadeprojects.com/SpecialAnimTwo) — цикл активного ремонта, [`SpecialAnimThree`](https://modenc.renegadeprojects.com/SpecialAnimThree) — закрывающая анимация (ключи общие с сервисным депо). Что на них показано (кран, створки, свет), не описано (не подтверждено).
- **Длительность и цикл:** по событию; порядок 1, 2, 3 по описаниям ModEnc; цикл (loop) назван только у второй, первая и третья однократные по смыслу (не подтверждено). Секунды и число кадров не подтверждены. Остановка цикла при нехватке денег (README) — предложение.
- **Для нашей модели:** `AnimationPlayer` с клипами `open` (первая стадия), `active` (цикл), `close` (закрытие); соответствие стадий клипам — предложение. Метка `repair_cell` на клетке дока и общий набор клипов с Ремонтным цехом — предложение (README: один компонент «ремонтная площадка»).

## Без энергии

README: энергия −20; в RA2 `Powered=true` (при дефиците не работает, точное поведение не подтверждено), в YR `Powered=false`: дефицит верфь не отключает. Изменение вида при этом appearance не описывает (не подтверждено). Предложение: как в простое, то есть как в YR (README: «предлагаю как в YR»). По ModEnc, общий механизм, источники расходятся: страница Powered говорит, что при `Powered=yes` активные и простойные анимации по умолчанию замирают при дефиците (`ActiveAnimPowered=no` это отменяет), страница ActiveAnimPowered — что по умолчанию (`yes`) они играют. Для ремонтных стадий `SpecialAnim` правило не описано; флаги верфи не сверены, в игре не сверено. `LowPower` играет только при обесточивании (вытягивание энергии, блэкаут шпиона, силовое поле), не при обычной нехватке.

## Повреждение и разрушение

- **До ~50% HP:** по ModEnc (`ConditionYellow`, общий механизм, порог по умолчанию 50% HP) показываются повреждённые кадры и анимация огня, а дымовые частицы и звук повреждения включаются ниже 50%; для верфи не сверено, appearance: отдельный вид не подтверждён. Для ремонтных анимаций есть damaged-ключи (`SpecialAnimDamaged` и варианты Two и Three), заданы ли они у верфи, не подтверждено. Дым и искры в `damage_*` на кране и доке — предложение.
- **До ~25% HP:** порог ~25% проектный, страница ModEnc ConditionRed пишет 50% (расхождение); вид верфи не подтверждён (appearance). Предложение: больше огня и густой дым в `damage_*`.
- **Разрушение:** по README верфь при гибели взрывается (`Explodes=yes`), выживших нет (`Crewed=no`); вид взрыва не описан (appearance). Предложение: взрыв и обломки, уходящие под воду (`debris_*`), руин нет. Судьба корабля в доке не описана (не подтверждено).

## Продажа и захват

- **Продажа:** по ModEnc без `Buildup` здание продать нельзя; у верфи `Buildup` есть (галерея вики, по appearance), а как выглядит продажа, не описано (не подтверждено). Предложение: `build_up` в обратную сторону. Выбегает ли кто-то при продаже, README не говорит.
- **Захват:** нет, инженер верфь не захватывает (README: `Capturable=no`), смены владельца не бывает. Цвет игрока: по ModEnc перекрашиваемые части анимаций берут цвет владельца (общий механизм); какие части верфи, не подтверждено (appearance); у нас — `team_color.gdshader`.

## Для нашей версии

- Нужно этому зданию: шейдер `build_up`; `damage_*` на кране, доке и платформе (места — предложение) и `debris_*` (предложение); клипы `open` / `active` / `close` под три стадии ремонта и метка `repair_cell` (предложение). `spin_*`, `smoke_*`, `light_*` источниками не подтверждены, без причины не вводить (предложение).
- Проверить в прототипе: (1) нужны ли все три стадии ремонта или хватит `active`, и сверить в оригинале, что они показывают и как корабль выходит из верфи (источники молчат); (2) как `build_up` с подсвеченной кромкой выглядит на воде и принимает ли здание точку сбора во время него (YR 1.001, README); (3) как цикл `active` прерывается без денег и как сочетается с огнём `damage_*`.
