# 03. Архитектура движка и симуляции

> Статус: черновик · Создан: 2026-10-21
> Родительский документ: [00_concept.md](00_concept.md), блок 3

Фундамент проекта. Ошибки здесь дороже всего: переделывать архитектуру потом означает переписывать всю игру. Главная цель — **детерминированная симуляция**, которая одинаково считается на любом компьютере, чтобы работали мультиплеер, повторы и отладка.

---

## 1. Общая схема

```
┌─────────────────────────────────────────────────────────┐
│                     Godot (клиент)                      │
│                                                         │
│   Ввод ──► Команды ──┐          ┌──► Отображение (3D)   │
│   (мышь,             │          │    Звук, эффекты, UI  │
│    клавиатура)       ▼          │                       │
│               ┌──────────────────────┐                  │
│   Бот ──────► │  Симуляция (чистый   │ ──► События      │
│               │  C#, детерминизм)    │     (выстрел,    │
│   Сеть ─────► │                      │      взрыв,      │
│               └──────────────────────┘      готово)     │
└─────────────────────────────────────────────────────────┘
```

- **Симуляция** — сердце игры. Получает команды, делает тик, выдаёт новое состояние и события. Ничего не знает о Godot, графике и звуке.
- **Отображение** — читает состояние симуляции и рисует его. Интерполирует между тиками для плавности.
- **Источники команд** — игрок, бот, сеть, файл повтора. Для симуляции они неразличимы.

## 2. Проекты в решении

| Проект | Что внутри | Зависит от |
|---|---|---|
| `Rts.Simulation` | Мир, сущности, правила, бой, экономика, поиск пути | Ничего (чистый .NET) |
| `Rts.Data` | Загрузка определений юнитов, зданий, оружия из файлов данных | `Simulation` |
| `Rts.AI` | Боты | `Simulation` |
| `Rts.Net` | Lockstep, протокол, сериализация команд | `Simulation` |
| `Rts.Client` | Godot-проект: отображение, ввод, UI, звук | Всё выше |
| `Rts.Server` | Лобби и ретранслятор (позже) | `Net` |
| `Rts.Analyzers` | Собственный Roslyn-анализатор детерминизма (RTS0001 — дробные числа, RTS0002 — неупорядоченный перебор) | Ничего |
| `Rts.*.Tests` | Модульные тесты и тесты детерминизма, по проекту тестов на каждый проект | Тестируемый проект |

`Rts` — нейтральное кодовое имя, не зависит от будущего названия игры. Детали реализации — в [implementation/M0_foundation.md](implementation/M0_foundation.md).

**Реализовано в M0:** `Rts.Simulation`, `Rts.Analyzers`, `Rts.Client`, проекты тестов. **В M2:** `Rts.Simulation.Benchmarks` (замеры). **В M7:** `Rts.Data` — формат карт `.rtsmap` (YamlDotNet, правила детерминизма), операции редактора карт и проверки карт; `Rts.MapGen` — генератор случайных карт (только `Rts.Data`, без Godot); утилита `tools/Rts.MapTool`; клиент читает карты через `Rts.Data`. **В M3:** `Rts.Data` загружает правила из YAML (`RulesLoader` — наследование и шаблоны, `RulesValidator` — все ошибки с файлом и строкой, `GameData` — правила, требования движка и хеш данных `DataHasher`); `Rts.MapTool economy` — сквозной прогон экономики. Остальные появляются в своих вехах ([implementation/conventions.md](implementation/conventions.md), раздел 1).

## 3. Детерминизм

**Правила, которые нельзя нарушать в симуляции:**

1. **Никакого `float` и `double`.** Только целые числа и фиксированная точка.
   - Позиции — в «лептонах», как в RA2: 1 клетка = 256 единиц.
   - Дробные величины (скорость, углы, проценты) — собственный тип `Fixed` (64-битное целое, 16 бит дробной части).
   - Тригонометрия и квадратный корень — через таблицы и целочисленные алгоритмы.
2. **Собственный генератор случайных чисел** с общим seed. Никакого `System.Random` и `Godot.GD.Randf`.
3. **Стабильный порядок.** Сущности обходятся по ID. Никаких перечислений `Dictionary`/`HashSet` в логике без сортировки.
4. **Никакого времени и окружения.** Симуляция не читает часы, файлы, сеть и настройки во время тика.
5. **Никакой многопоточности внутри тика** (по крайней мере пока не доказано, что это детерминированно).

**Как правила соблюдаются (M0):**
- **Компилятором.** У проектов симуляции — флаг `RtsDeterministic`: нарушение правил 1–5 — ошибка сборки. Запрещённые API ловит BannedApiAnalyzers (`BannedSymbols.txt`), а ключевые слова `float`/`double`/`decimal`, дробные литералы и перебор `Dictionary`/`HashSet` — собственный анализатор `Rts.Analyzers`.
- **Контрольной суммой.** FNV-1a 64 по всему состоянию после каждого тика; тест-охранник падает, если поле состояния не учтено в хеше. С M2 в сумму входят: тик, генератор, следующий номер сущности, карта (дайджестом слоёв земли, препятствий и, с M7, высот углов — пересчитывается только после изменения карты), очередь запросов пути и число раскрытых узлов незаконченных поисков, занятые места техники и пехоты (только занятые, парами «место — юнит»), все поля юнитов, их пути (дайджестом) и маршруты.
- **«Золотыми» значениями.** Генератор, математика, контрольные суммы и байты повтора эталонной партии зашиты в тесты; CI на Linux, macOS и Windows обязан воспроизвести их бит-в-бит. Первый прогон M0 — совпало на всех платформах.

Реализация: `Fixed` (Q47.16, промежуточные вычисления в `Int128`), `IntMath` (целочисленный корень, деление с округлением), генератор PCG32, позиции в лептонах (`WorldPos`).

## 4. Тики и время

- **Тик симуляции:** фиксированный, **15 тиков в секунду** — окончательно (решение по итогам M2): скорости юнитов пересчитаны из RA2 под эту частоту, темп движения проверен вручную.
- **Главный класс** — `GameSimulation`: `Step()` выполняет тик в фиксированном порядке ([implementation/conventions.md](implementation/conventions.md), раздел 5). Порядок M2: команды тика (по игроку и номеру) → очередь путей (до 6 000 раскрытых узлов A* за тик, незаконченный поиск продолжается на следующем) → движение юнитов по номеру → синхронизация пространственного индекса → удаление погибших → тик + 1 → контрольная сумма. **Порядок M3:** команды → очередь путей → энергия → производство → вырастание зданий → харвестеры → ремонт → движение → пространственный индекс → рост руды → тех-дерево → удаление погибших → тик + 1 → контрольная сумма ([implementation/M3_base_economy.md](implementation/M3_base_economy.md), 4.15).
- **Отрисовка:** 60+ FPS, с интерполяцией позиций между тиками.
- **Скорость игры:** меняется числом тиков в секунду, логика тика не меняется.
- **Задержка ввода:** команда исполняется на тике `текущий + N`. В одиночной игре N минимален, в сети подстраивается под пинг.

## 5. Команды

Всё, что меняет мир, — команда:

| Пример | Параметры |
|---|---|
| `Move` | юниты, точка, режим (обычный / атака-движение) |
| `Attack` | юниты, цель |
| `Build` | тип здания, клетка |
| `Produce` / `CancelProduction` | фабрика, тип юнита |
| `Sell`, `Repair` | здание |
| `Deploy` | юнит (MCV, IFV и т. п.) |
| `UseSuperweapon` | тип, точка |

Каждая команда: номер игрока, тик исполнения, компактная бинарная сериализация. Поток команд — это одновременно сетевой протокол и формат повтора.

**Реализовано в M2** (формат команд v3, повтора v4): появление юнита (отладка), `Move` с флагом очереди, `AttackMove` (пометка; сама атака — M4), `Waypoints` (1…32 точки, патруль), `Stop`, `Scatter`; до 256 юнитов в команде.

## 6. Модель мира

- **Сущности:** юниты, здания, снаряды, эффекты-с-логикой (радиация, ящики). У каждой — стабильный ID.
- **Подход:** простые классы с компонентами по необходимости. Полноценный ECS — только если упрёмся в производительность.
- **Карта:** сетка клеток с высотами, типом земли, проходимостью, рудой, занятостью.
- **Пространственный индекс** для быстрых запросов «кто рядом» (сетка-бакеты).
- **Реализовано в M2:** `MapGrid` — тип земли и препятствие на клетку (высоты станут правилами в M7); `Reservations` — кто стоит в клетке (техника) и на каком из 5 мест (пехота); `SpatialIndex` — бакеты 4×4 клетки, производная структура, в хеш не входит; поиск пути — A* с бюджетом узлов на тик и сглаживанием «натянутой нитью».
- **Определения отдельно от экземпляров:** «Тяжёлый танк» (данные) ≠ «танк #1532» (экземпляр).

---

## 7. Связь симуляции и отображения

- Симуляция выдаёт **события** (выстрел, попадание, смерть, постройка завершена) — отображение проигрывает эффекты и звуки.
- Отображение **никогда не меняет** состояние симуляции. Только через команды.
- Для каждой сущности симуляции — визуальный узел Godot (пул объектов, чтобы не создавать заново).

---

## 8. Данные

- Определения юнитов, зданий, оружия, брони — в файлах **YAML** в `game/data` (с M3; справочник ключей — [formats/data.md](formats/data.md)).
- Загружаются при старте (`Rts.Data.GameData`) и превращаются в неизменяемые определения; ошибка в данных — сообщение с файлом и строкой, игра не стартует. Симуляция получает правила (`GameRules`) и не знает параметров юнитов и зданий в коде.
- Хеш данных (`DataHasher`) записывается в повтор; в сетевой игре — сверяется у всех игроков перед стартом.
