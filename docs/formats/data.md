# Файлы данных `game/data`

> Для тех, кто правит баланс. Создан: 2026-10-22 (закрытие M3), бой — M4, шаги 1–14. Подробности реализации и решения — [M3_base_economy.md](../implementation/M3_base_economy.md), 4.1–4.5; [M4_combat.md](../implementation/M4_combat.md), 4.3.

Все игровые параметры юнитов, зданий, экономики, земли и передвижения лежат в YAML-файлах в `game/data`. Игра читает их при старте, баланс правится без перекомпиляции.

Проверить данные без запуска игры:

```bash
dotnet run --project tools/Rts.MapTool -- rules
```

Команда печатает число записей и хеш данных или список всех ошибок. Темп экономики на текущих данных — `dotnet run --project tools/Rts.MapTool -- economy frozen-crossing`.

## 1. Где что лежит

```

├── shared/
│   ├── locomotors.yaml     типы передвижения
│   ├── terrain.yaml        типы земли: код карты, можно ли строить, скорости
│   ├── templates.yaml      абстрактные шаблоны (base_infantry, base_vehicle, base_building, base_defense)
│   └── economy.yaml        общие правила экономики (ровно одна запись)
├── combat/                 бой (M4)
│   ├── armor.yaml          типы брони
│   ├── warheads.yaml       боеголовки: доля урона по каждой броне, площадь
│   └── projectiles.yaml    снаряды: как долетают
├── factions/
│   ├── factions.yaml       фракции
│   └── union/
│       ├── buildings.yaml
│       ├── units.yaml
│       └── weapons.yaml    оружие юнитов и обороны
├── ai/                     боты (M5, M8)
│   ├── difficulty.yaml     уровни ботов: ai_easy, ai_medium, ai_hard, ai_brutal
│   ├── personalities/      характеры ботов, по файлу на характер (M8)
│   └── union.yaml          порядки постройки и состав армии Союза
└── maps/                   готовые карты (формат — rtsmap.md)
```

Раскладка по файлам — для удобства людей: загрузчик читает все `*.yaml` под `game/data` и собирает записи вместе (карты — файлы `.rtsmap`, их он не читает). Порядок файлов и записей ни на что не влияет.

## 2. Записи

Файл — словарь записей. Ключ верхнего уровня — `id` записи: латиница в нижнем регистре, цифры и `_`. Он уникален во всех файлах и во всех видах: броня `flak` и снаряд `flak` не уживутся.

```yaml
reactor:  # Tesla Reactor
  kind: building
  inherits: base_building
  name: Reactor
  faction: union
  cost: 600
  build_time: 25.2s
  hp: 750
  footprint: [2, 2]
  power: 150
  prerequisites: [construction_yard]
```

| Служебный ключ | Смысл |
|---|---|
| `kind` | Вид записи: `unit`, `building`, `weapon`, `locomotor`, `terrain`, `faction`, `economy`, `armor`, `warhead`, `projectile`. Обязателен (можно взять из шаблона) |
| `inherits` | `id` шаблона или другой записи того же вида: её ключи берутся как значения по умолчанию, свои ключи их переопределяют. Цепочки разрешены, циклы — ошибка |
| `abstract: true` | Шаблон: определения не создаёт, только наследуется |

Неизвестный ключ — ошибка (опечатка не пройдёт молча).

---

## 3. Значения

| Тип | Как писать | Пример |
|---|---|---|
| Целое | Целое число | `cost: 600`, `power: -50` |
| Проценты | Число со знаком `%` | `slope: 20%`, `sell_refund: 50%` |
| Время | Секунды с `s`; переводится в тики (15 в секунду), округляется | `build_time: 25.2s` → 378 тиков |
| Флаг | `true` / `false` | `turret: true` |
| Пятно, клетка | Пара целых `[x, y]` | `footprint: [3, 4]`, `exit_cell: [1, 4]` |
| Список `id` | `[a, b]` | `prerequisites: [war_factory, radar]` |
| Текст | Строка | `name: Heavy Tank` |

Дробные числа читаются в фиксированную точку без `float` — одинаково на всех платформах. Запятая вместо точки (`1,5`), экспонента (`1e3`) и лишние символы — ошибки.

Колонка «Нужен» — обязателен ли ключ в итоговой записи (после наследования).

| `unload_rate` | целое | нет | Кредитов за тик при разгрузке |

### `faction`

| Ключ | Смысл |
|---|---|
| `name` | Название |
| `mcv` | `id` юнита, который разворачивается в базу |
| `construction_yard` | `id` здания из MCV; заказать его нельзя |
| `refinery` | `id` ОПЗ: готовый даёт бесплатный харвестер |
| `harvester` | `id` харвестера |

### `build_order` (боты, M5)

Порядок, в котором бот строит базу. Бот идёт по шагам по очереди. Потерянное здание из порядка он строит заново. Срочное — реактор при нехватке энергии, потерянный ОПЗ — ставит раньше.

| Ключ | Смысл |
|---|---|
| `faction` | `id` фракции |
| `steps` | `id` зданий этой фракции по порядку; здание может повторяться (второй ОПЗ) |

Оборону бот сам ставит на сторону вероятного врага — отдельного ключа не нужно. Какой порядок берёт бот, задаёт характер (`build_orders`), а какое из трёх качеств — уровень (`build_order_quality`).

### `army` (боты, M5)

Какую армию собирает бот: доля каждого вида юнитов. Вид, который пока нельзя строить (нет фабрики, тех-центра), свою долю не получает. Остальные её не забирают: армия не перекашивается в пехоту, пока нет завода.

| Ключ | Смысл |
|---|---|
| `faction` | `id` фракции |
| `shares` | Доли юнитов этой фракции, `heavy_tank: 40%`; вместе — 100 % |
| `against_infantry` | Юниты, которые получают долю, когда у врага больше половины пехоты (давят, косят) |
| `against_vehicles` | Юниты, которые получают долю, когда у врага больше половины техники (противотанковые) |

`against_infantry` и `against_vehicles` — таблица контр (M8, шаг 7). Доля армии `counter_pick` уровня строится под состав врага: доля его пехоты уходит юнитам `against_infantry`, доля техники — `against_vehicles`, остальное — доли `shares`. Какой состав берёт бот, задаёт характер (`armies`): у всех пока `standard_army`.

### `difficulty` (боты, M5 шаг 14, M8 шаг 1)

Уровень бота: `ai_easy`, `ai_medium`, `ai_hard`, `ai_brutal` — «Лёгкий», «Средний», «Сложный», «Жестокий». Id не `medium`: id общие на все данные, а `medium` — броня. Все ключи обязательны. Общее для уровней лежит в шаблоне `ai_level` (`abstract: true`), уровень наследует его и пишет своё.

| Ключи | Что | Как пишется |
|---|---|---|
| `strategy_period`, `economy_period`, `build_period`, `production_period`, `scouting_period`, `tactics_period`, `defense_period` | Как часто думает каждый модуль | тики, > 0 |
| `max_refineries`, `harvesters_per_refinery`, `power_reserve`, `danger_cells`, `second_factory_credits` | Экономика | числа; `power_reserve` — % |
| `harvesters` | Харвестеры (M8, шаг 10): всегда `harvesters_per_refinery` на ОПЗ — или по руде в 24 клетках от ОПЗ, один на 4 своих цены, не больше того | `fixed`, `by_ore` |
| `infantry_queued`, `vehicles_queued` | Армия: юнитов в очереди казарм и завода | числа |
| `scouting_interval`, `scout_block_cells`, `scout_danger_cells` | Разведка | интервал — длительность (`180s`) |
| `min_attack_army`, `attack_growth_per_wave`, `attack_threshold`, `retreat_at_strength`, `gather_cells`, `squad_spread_cells`, `engage_cells`, `wounded`, `sweep_places` | Отряды | доли — %; рост волн ≥ 100 %, отступление < 100 % |
| `all_in_after`, `all_in_units`, `sell_every` | Когда руда кончилась | длительности — `120s`, `30s` |
| `perception_delay`, `threat_clear`, `base_cells`, `max_defenses` | Оборона базы | длительности — `1s`, `10s` |
| `actions_per_second`, `mistake_chance` | Лимит команд в секунду, шанс взять не лучший вариант из трёх (M8, 4.3) | число > 0; % |
| `micro` | Микро в бою (M8, 4.4) | `none`, `focus`, `retreat_wounded`, `keep_range` |
| `scouting` | Разведка (M8, 4.6) | `none`, `periodic`, `constant`, `constant_expansions` |
| `counter_pick` | Доля армии под состав врага (M8, шаг 7): по таблице контр `army`, остальное — армия характера | % |
| `first_attack_delay` | Самая ранняя атака | длительность; `0s` — по окну характера |
| `parallel_squads` | Отрядов одновременно | число > 0 |
| `defend_harvesters` | Защищает ли харвестеры | `no`, `yes` |
| `expansion` | Второй ОПЗ у дальних полей | `none`, `late`, `early` |
| `build_order_quality` | Какой порядок характера брать | `simple`, `standard`, `optimized` |
| `rebuild_destroyed` | Восстановление потерянного | `partial`, `yes`, `priority` |
| `attack_knowledge` | Что бот должен знать о враге перед атакой (M8, шаг 10а): взгляд на армию или в почти пустую базу — или только на саму армию и отбитую атаку | `base`, `army` |
| `income_bonus`, `build_speed_bonus` | Бонусы игрока (M8, 4.5): кредитов сверх руды, скорость стройки по той же цене | %, от 0 до 100; у «Жестокого» `40%`, `20%` |
| `reveal_map` | Игрок видит всю карту: его приказы и юниты, туман на экране остаётся | `no`, `yes` |

- Слово не из списка — ошибка в его строке, с перечнем допустимых слов.
- Доли (`power_reserve`, `wounded`, `mistake_chance`, `counter_pick`) — не больше 100 %.
- Ключи M8 бот пока не использует: они нужны шагам 3–7 M8, но уже проверяются и входят в хеш.
- Бонусы игрока действуют с шага 2 M8: их берёт симуляция при старте партии — у бота этого уровня, не у человека.
- Код держит числа «Среднего» в `AiSettings.Medium`. Тест требует равенства: модули проверяются на числах игры.

### `personality` (боты, M8 шаг 1)

Характер бота: как он играет; уровень — насколько хорошо. Файлы — `ai/personalities/`, по одному на характер: `balanced`, `aggressor`, `builder`, `saboteur`. Пока бот партии всегда «Сбалансированный»; выбор характера — шаги 8 и 13 M8. Все ключи обязательны.

| Ключ | Что | Как пишется |
|---|---|---|
| `name` | Название | текст |
| `weights` | Что важнее стратегу | `{ economy: 1, defense: 1, army: 1, tech: 1, harassment: 1 }` — все пять, числа ≥ 0, в сумме не обязательно 1 |
| `armies` | Армия на каждую фракцию | `{ union: standard_army }` — id записей `army` этой фракции |
| `build_orders` | Порядки на каждую фракцию, по качеству | `union: { simple: …, standard: …, optimized: … }` — id записей `build_order` этой фракции |
| `first_attack` | Окно первой атаки для уровней «по характеру» | `{ min: 360s, max: 480s }`, min ≤ max |
| `wave_interval` | Между волнами | длительность > 0 |
| `retreat_threshold` | Отряд отходит, когда своя сила ниже этой доли вражеской рядом | больше 0 %, не больше 100 % |
| `target_priority` | Цели по порядку | все шесть ровно раз: `production`, `army`, `power`, `harvesters`, `defense`, `core` |

У каждой фракции данных должны быть армия и три порядка в каждом характере: новая фракция без них не загрузится.

**Что из характера действует** (M8, шаг 8):
- `armies`, `build_orders` — армия и порядок постройки, качество порядка — по уровню.
- **Веса** — к числам уровня:
  - `economy` — ОПЗ до `2 × вес`;
  - `defense` — обороны до `3 × вес`;
  - `army` — второй завод с `4000 / вес` кредитов;
  - `tech` пока не действует;
  - `harassment` — через цели.
- `first_attack` — окно первой атаки «Сложного» и «Жестокого». У «Лёгкого» и «Среднего» — `first_attack_delay` уровня.
- `wave_interval` — волны не чаще.
- `retreat_threshold` — отход отряда, проигрывающего размен (шаг 5).
- `target_priority` — цели отряда: `harvesters` — ОПЗ, `defense` — с оружием, `production` — казармы и заводы, `core` — стройплощадка, `power` — электростанции; прочие здания — после всех. Ошибка во вложенном поле указывает на его строку и столбец: лишний ключ — с перечнем допустимых, пропущенный — по имени.

|---|---|---|

| `ore_growth_chance` | проценты | Шанс клетки дорасти на стадию |
| `ore_spread_stage` | целое 0–11 | С какой стадии клетка засеивает соседнюю |

### `weapon`

Цепочка боя, как в RA2: **оружие** знает, сколько и как часто, **снаряд** — как долетает, **боеголовка** — по чему и как сильно. Одну боеголовку используют многие виды оружия.

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `damage` | целое | да | Урон одного выстрела до брони |
| `reload` | время | да | Между выстрелами (RA2 `ROF` / 15 с: тик — кадр RA2) |
| `range` | клетки, дробное | да | Дальность, > 0 |
| `min_range` | клетки | нет (0) | Ближе цель нельзя; меньше `range` |
| `projectile` | `id` снаряда | да | Чем стреляет |
| `warhead` | `id` боеголовки | да | Что делает попадание |
| `burst` | целое ≥ 1 | нет (1) | Выстрелов в очереди |
| `burst_delay` | время | нет (0) | Между выстрелами очереди |
| `targets` | список из `ground`, `air` | нет (`[ground]`) | По кому стреляет |
| `report` | `id` | нет | Звук выстрела, для клиента |

### `armor`

Только `name`. Номер брони — её место по `id`; порядок записей ни на что не влияет. Союз: `none`, `flak`, `plate` (пехота), `light`, `medium`, `heavy` (техника), `wood`, `steel`, `concrete` (здания), `special_1`, `special_2` (про запас).

### `warhead`

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `verses` | словарь «броня: проценты» | да | Доля урона по каждой броне (RA2 `Verses`), 0–1000 %; перечислить **все** типы брони |
| `spread` | клетки, дробное | нет (0) | Радиус площади; 0 — только цель |
| `percent_at_max` | проценты 0–100 | нет (100 %) | Доля урона на краю площади |
| `wall_damage` | флаг | нет | Бьёт ли стены |
| `affects_air` | флаг | нет | Задевает ли авиацию в площади |
| `infantry_death` | `id` | нет | Как гибнет пехота, для клиента |

```yaml
ap_shell:  # RA2 AP
  kind: warhead
  name: Armor Piercing
  verses: { none: 25%, flak: 25%, plate: 25%, light: 75%, medium: 100%, heavy: 100%, wood: 65%, steel: 45%, concrete: 45%, special_1: 100%, special_2: 100% }
  spread: 0.3
  percent_at_max: 50%
  wall_damage: true
```

| Вид | Ключи |
|---|---|

## 5. Проверки и ошибки

Загрузчик собирает **все** ошибки сразу. Каждая — с файлом, строкой и колонкой:

```
game/data/factions/union/units.yaml:20:3: 'speed' of 'heavy_tank' must not be negative
```

Проверяется:
- **синтаксис:** YAML, значения, неизвестные ключи;
- **наследование:** нет шаблона, цикл; якоря YAML (`&`, `*`) запрещены — наследование только через `inherits`;
- **ссылки:** фракция, передвижение, пререквизиты; броня юнитов и зданий, их оружие; снаряд и боеголовка оружия; броня в `verses`;
- **диапазоны:** цены, время и прочность не отрицательные; `adjacent` 0–10; пятно 1–6; клетки выхода и дока в пятне или рядом; проценты экономики; у оружия перезарядка и дальность > 0, `burst` ≥ 1, `min_range` < `range`; `verses` 0–1000 % и по каждой броне; летящему снаряду — скорость, самонаводящемуся — ещё поворот и время жизни;
- **смысл боевых ключей:**
  - давит только техника (`placement: cell`), давится только пехота (`placement: subcell`);
  - стена (`wall: true`) — пятно 1×1 и `extends_base: false`;
  - `threat` и `sight` не отрицательные;
  - `stance` — один из `aggressive`, `guard`, `hold`;
- **требования движка:** у фракции есть стройплощадка, ОПЗ, MCV и харвестер; все типы земли и передвижения на месте.

С ошибкой в данных игра не стартует: печатает ошибки и закрывается с кодом 1.

## 6. Хеш данных

Хеш данных (`DataHasher`) считается по значениям, а не по тексту: пробелы, комментарии, порядок файлов и записей его не меняют, любое число — меняет. Хеш пишется в повтор. Повтор, записанный на других данных, проигрывается с предупреждением. Тест `GameDataTests` закрепляет хеш `game/data`: правка данных требует обновить его в том же коммите. В сетевой игре хеш будет сверяться перед стартом.
