## 1. Цель и результат

**Цель:** первая настоящая партия. Против игрока играет бот, который строит базу, добывает руду, собирает армию, разведывает и атакует. У партии есть начало, условия победы и поражения и экран итогов.

**Что будет работать в конце вехи:**

1. Новый проект `Rts.AI`: бот работает **внутри детерминированной симуляции** и действует только командами.
2. Бот видит только то, что видит его игрок (туман войны), и помнит последнее увиденное.
3. Модули бота: стратег, экономика, планировщик построек, производство армии, разведка, тактика отрядов, оборона.
4. Уровень сложности «Средний» и характер «Сбалансированный». Параметры — в YAML, чтобы следующие уровни (M8) были настройкой, а не новым кодом.
5. Условия победы и поражения, событие конца партии.
6. Статистика партии и экран итогов.
7. Минимальный запуск скирмиша: 1 человек против 1 бота на тестовой карте.
8. Отладочный оверлей «что думает бот».

**Критерий из [01_vision.md](../01_vision.md):** хочется сыграть вторую партию, даже с заглушками вместо моделей.

## 4. Технические решения

### 4.1. Где бот работает

**Решение: бот — часть детерминированной симуляции.** Он запускается на каждом компьютере в сетевой игре одинаково, как в RA2.

| Вариант | Плюсы | Минусы | Выбор |
|---|---|---|---|
| Бот внутри симуляции на всех клиентах | Нет сетевой задержки и зависимости от хоста; бесплатная синхронизация | Код бота обязан быть детерминированным | **Да** |
| Бот только у хоста, команды по сети | Бот может быть недетерминированным | Задержка, зависимость от хоста, лишний трафик | Нет |

**Следствие:** к коду `Rts.AI` применяются **те же правила детерминизма**, что к симуляции: анализатор запрещённых API (`BannedSymbols.txt` из M0) подключается и к `Rts.AI`.

**Как сделано (шаг 1):**
- `Rts.AI.csproj` ставит `RtsDeterministic`, ссылается только на `Rts.Simulation`. `Rts.Data` подключится с данными бота.
- Проверено сборкой: `double` в `Rts.AI` — ошибка RTS0001, `System.Random` — RS0030.
- **Тесты** (`DeterministicProjectsTests` в `Rts.Analyzers.Tests`):
  - у Simulation, Data, MapGen и AI в проекте стоит флаг, ссылок на Godot нет;
  - настоящие исходники `Rts.AI` проходят анализатор чисто;
  - с подброшенным `double` анализатор выдаёт RTS0001.

### 4.2. Место в тике

```
1. Применить команды тика T (людей и ботов — одинаково)
2. Системы симуляции (движение, бой, экономика, ...)
3. Удалить мёртвых
4. Боты думают: читают состояние после тика T, выдают команды на тик T + 1
5. T = T + 1, контрольная сумма
```

- Команды бота проходят через ту же `CommandQueue` и ту же проверку, что команды игрока. **Никаких прямых изменений мира.**
- `PlayerId` бота — обычный игрок; `Sequence` у бота свой, как у любого игрока.

**Как сделано (шаг 1).**
- **Симуляция** — `src/Rts.Simulation/Ai/`:
  - `IAiController`: `Player`, `Think(AiTurn)`;
  - `AiTurn` — ход бота: мир после тика T (только читать), `Tick`, `ExecuteTick` = T + 1, `NextSequence()`, `Issue(Command)`. Команда идёт в общую очередь; команда чужого игрока или на другой тик — исключение: это ошибка кода бота, а не игры.
- **Подключение** — `GameSimulation.AttachAi`, явно и только в живой партии:
  - один бот на игрока, игроки 1–8;
  - боты думают по порядку `PlayerId`, после удаления погибших, до `T + 1` (фаза `bots` у `Probe`);
  - повтор ботов не подключает: `ReplayPlayer` ставит записанные команды в очередь сам, бот задвоил бы их.
- **Номера команд бота** — с `0x8000_0000`. Они не столкнутся с номерами человека, который отладочно (F11) играет за того же игрока.
- **Эталоны:** без ботов поведение прежнее; `SimulationVersion` прежний — 37, все эталоны те же.
- **`Rts.AI`:**
  - `AiPlayer` — один бот, модули `IAiModule`, по одному каждого вида; без модулей — пустой бот;
  - `AiSchedule` — расписание 4.3;
  - `AiSettings.Medium` — периоды в коде, в YAML — на шаге 14.
- **Отложено:**
  - пометка «бот» у команд в повторе и режим «перезапустить ботов» — на шаг 2, вместе с `MatchSetup` в повторе: формат повтора меняется один раз;
  - счётчик отброшенных команд бота — на шаг 4, с первыми настоящими командами. Сейчас `Apply` отвечает «мир изменился», а не «команда принята».
### 4.3. Бюджет «мышления» без часов

Ограничивать бота по **времени** нельзя — время недетерминировано. Ограничиваем по **расписанию и счётчикам**:

| Модуль | Как часто | Сдвиг |
|---|---|---|
| Стратег | Раз в 45 тиков (3 с) у «Среднего» — по M8, раздел 4.2 | `playerId × 3` |
| Экономика | Раз в 15 тиков | `+1` |
| Планировщик построек | Раз в 15 тиков | `+2` |
| Производство | Раз в 15 тиков | `+4` |
| Разведка | Раз в 45 тиков | `+5` |
| Отряды (тактика) | Раз в 15 тиков (1 с) у «Среднего» — по M8, раздел 4.2 | `+0` |
| Оборона | Раз в 5 тиков | `+3` |

- Сдвиги разносят работу модулей и разных ботов по разным тикам.
- **Как сделано (шаг 1):** модуль думает после тика T, когда `(T + игрок × 3 + сдвиг) % период == 0`. На общем тике модули идут в порядке таблицы: стратег, экономика, постройки, производство, разведка, отряды, оборона (`AiModuleKind`).
- Дорогие операции (поиск места для здания, оценка целей) ограничены **числом проверок за вызов** (например, не больше 200 клеток на поиск места), а не временем. Незаконченный поиск продолжается на следующем вызове.

### 4.4. Повторы и боты

**Решение:** повтор записывает команды ботов так же, как команды людей (с пометкой «бот»). При просмотре повтора боты **не запускаются** — используются записанные команды.

- Плюс: повтор не ломается при изменении кода бота (ломается только при изменении правил симуляции, как и раньше).
- Для тестов детерминизма есть режим «перезапустить ботов» — тогда команды ботов из повтора сравниваются с заново сгенерированными.

**Как сделано (шаг 2):**
- **Пометка «бот» — без нового байта в команде.** В описании партии видно, какой игрок — бот. Его команды с номером от `AiTurn.FirstSequence` — команды бота (`ReplayPlayer.IsBotCommand`). Человек, играющий за того же игрока по F11, пишет номерами от 0 — его команды ботом не считаются.
- **Режим «перезапустить ботов»** — `ReplayPlayer.VerifyWithBots(replay, rules, createBot)`:
  - ставит в очередь всё, кроме команд ботов;
  - подключает ботов, созданных `createBot` (в игре — `MatchBots.Create`);
  - сверяет суммы и побайтно — команды ботов с записанными. Иначе — `ReplayStatus.BotsDiffer`.

  Обычный `Verify` и F9 в клиенте играют без ботов.

### 4.5. Мир глазами бота

`AiWorldView` — единственный способ бота читать мир:

- свои сущности — полностью;
- союзные — полностью;
- вражеские — **только в видимых клетках** по сетке видимости из M4;
- карта: рельеф и проходимость — только в разведанных клетках (в завесе бот, как и игрок, ничего не знает); для поиска пути в неразведанное используется предположение «проходимо», как у юнитов игрока;
- руда — только в разведанных клетках.

`AiMemory` хранит последнее увиденное:

| Что | Хранится | Забывается |
|---|---|---|
| Вражеские здания | Тип, позиция, тик наблюдения | Когда клетку снова увидели, а здания нет |
| Скопления вражеской армии | Центр, примерная сила, тик | Через 60 секунд |
| Стартовые позиции врагов | Из настроек карты: известны все возможные старты, но не какой занят | Когда разведан |

Это гарантирует честность: «Средний» бот не знает, где игрок, пока не найдёт его.

**Как сделано (шаг 3).**
- **`Rts.AI/View/AiWorldView`** — пересобирается каждый ход бота. В нём:
  - свои юниты и здания — всегда;
  - союзные — `IsAlly` по `AlliesOf`;
  - видимые враги — `Vision.Sees`;
  - клетки: `StateOf`, `IsExplored`, `IsVisible`; `LandAt` (`null` в завесе), `OreAt` (пусто в завесе);
  - `CanEnter`: в завесе — «можно»; в тумане чужое здание клетку не закрывает — что бот о нём знает, лежит в памяти, а не в карте;
  - свой `PlayerState`, правила, размер карты, свой старт и все старты карты.

  Ссылки на мир нет.
- **`AiMemory`** — обновляется каждый ход, до модулей:
  - **здания** — по номеру; в тумане помнятся, забываются, когда видна клетка пятна, а здания нет (разрушено, продано);
  - **армии** — по блокам 8×8: центр, сила (цена × доля прочности), число, тик. Забываются через 900 тиков (60 с) или когда центр блока виден без них;
  - **возможные старты врага** — старты карты кроме своего, пока не разведаны. На карте на двоих это сразу один старт, как в RA2.
- **Все старты карты — в описании партии** (`MatchSetup.MapStarts`, повтор v18). Без этого возможные старты пришлось бы брать из занятых, и бот знал бы, где враг на картах на 4 игрока. `Problem` требует, чтобы старт игрока был среди стартов карты.
- **Модули получают `AiContext`**: вид, память, тик и выдачу команд. Мира в нём нет. Тест `AiContextTests` отражением проверяет, что из контекста, вида и памяти не дотянуться до `GameWorld`, `GameSimulation`, `AiTurn` и генератора случая.
- **Отклонения:**
  - союзников проверить нечем: `AlliesOf` — заглушка M4, враждебность от команд не зависит; команды — M6/M8;
  - руда в разведанной клетке — какая есть сейчас, а не последняя увиденная;
  - вражеские здания вне видимых клеток узнаются только памятью.

### 4.6. Модули бота

**Стратег** — конечный автомат верхнего уровня:

```
           ┌────────────┐
  старт ──►│  Развитие  │──── армия ≥ порога ───►┌─────────┐
           │ (опенинг)  │                        │  Атака  │
           └─────┬──────┘◄─── волна закончилась ─┴────┬────┘
                 │                                    │
        база атакована                       база атакована
                 ▼                                    ▼
           ┌────────────┐                       ┌──────────┐
           │  Оборона   │◄──────────────────────┤  Оборона │
           └────────────┘   угроза снята → назад└──────────┘
```

Стратег выставляет **приоритеты** для остальных модулей (сколько денег на экономику, армию, оборону), а не управляет юнитами напрямую.

**Экономика:**
- держит целевое число харвестеров: 2 на ОПЗ, максимум ОПЗ — по параметрам уровня;
- следит за энергией: при запасе меньше 20% планирует реактор;
- восстанавливает потерянные харвестеры и ОПЗ в первую очередь;
- отправляет харвестеров на поля, удалённые от известных врагов.

**Как сделано (шаг 4).**
- **`Modules/EconomyManager`** (раз в 15 тиков). Нужды экономики — в `AiPlan.Wants`, по порядку:
  1. потерянный ОПЗ (их меньше, чем было лучшее число) или первый ОПЗ;
  2. завод, если харвестеров не хватает, а сделать их негде;
  3. реактор — первым, если следующее нужное здание оставит базу без энергии; после потерянного ОПЗ — если запас (выход − расход, с заказанными и растущими зданиями) меньше 20 % выхода.

  Харвестеров заказывает сам, по одному, до 2 на ОПЗ. Харвестер работает в 12 клетках от известного врага — от армии из памяти или вооружённого здания — его отправляют на разведанную руду, ближайшую к своим ОПЗ и не ближе 12 клеток к врагам.
- **Реактор и завод фракции** определяются по данным, без имён: реактор — самое дешёвое здание с энергией, завод — здание, которое производит технику.
- **`Modules/BuildPlanner` — пока минимальный**, шаг 5 его заменит.
  - **MCV:** разворачивается, где стоит; если стройплощадка там не встаёт — едет на ближайшую разведанную клетку в 6 клетках, где встаёт. Если такой не видно (старт в яме `relief_test`) — едет на 4 клетки к середине карты, смотрит заново.
  - **Постройка:** при пустой очереди заказывает первое из `Wants`, что доступно и по карману. Готовое ставит, как сценарный игрок M3 (`EconomyRun.Spot`), но через вид: у стройплощадки, где правила разрешают и вокруг кольцо без своих зданий; ОПЗ — ближе к разведанной руде.
- **`AiWorldView`:**
  - `CanPlace` — `PlacementRules`, но только для разведанных клеток пятна;
  - `HasFactory`.
- **`AiSettings`:** `MaxRefineries`, `HarvestersPerRefinery`, `PowerReservePercent`, `DangerCells`.
- **Бот «Средний»** (`MatchBots`) получил эти два модуля.

**Планировщик построек:**
- идёт по порядку постройки (build order) из YAML;
- после завершения порядка — правила «по потребности» (энергия, вторая фабрика, оборона на направлении атак);
- не начинает здание, на которое нет денег с учётом текущих трат.

**Размещение зданий (`BasePlacement`):**

```
1. Кандидаты — клетки по спирали от стройплощадки в радиусе строительства
2. Отбрасываем: занятые, непроходимые, перекрывающие руду, вплотную к краю карты
3. Оценка:
   + близость к стройплощадке
   + для ОПЗ — близость к ближайшему полю руды
   + для обороны — направление на известного/вероятного врага
   − перекрытие проходов (проверка: после размещения путь от фабрик к краю базы существует)
   − соседство с другими зданиями вплотную (оставляем проезды в 1 клетку)
4. Лучший кандидат; равные — меньший (Y, X)
```

**Производство армии:**
- целевой состав армии из `compositions/union.yaml` (проценты по ролям);
- «Средний» уровень учитывает видимый состав врага **грубо**: если у врага > 50% пехоты — сдвиг к давящей технике, если > 50% техники — к противотанковым;
- держит очереди фабрик заполненными, пока есть деньги и стратег разрешает.

**Разведка:**
- в начале партии — один дешёвый юнит к ближайшим возможным стартам врага;
- далее — периодическая проверка неразведанных полей руды и последних позиций врага;
- разведчик отступает при встрече с армией.

**Как сделано (шаг 7).**
- **`Modules/ScoutManager`** (раз в 45 тиков). Разведчик — один юнит, его номер в `AiPlan.Scout`: отряды шага 8 его не возьмут.
  - Сначала — самый дешёвый свой боевой юнит, не харвестер: призывник со старта.
  - Погиб — на следующем ходу назначается новый так же.
- **Начало партии.** Пока бот не видел ни одного врага (`AiMemory.EnemySeen`), разведчик идёт к ближайшему из `PossibleEnemyStarts`. Разведанный старт память снимает — тогда к следующему.
- **Дальше — вылазки раз в `ScoutingInterval` (2700 тиков, 3 минуты).** Вылазка — до 4 мест подряд, потом домой. Место — по важности:
  1. середина неразведанного блока 16×16, ближайшего к своему старту. Так находятся дальние поля руды;
  2. всё разведано — вражеское здание из памяти, не виденное дольше всех (старше 2 минут).

  Место достигнуто (2 клетки) или стало видно — следующее. С одним местом за вылазку разведка шла заметно медленнее; с четырьмя к 15-й минуте — 63 % Frozen Crossing.
- **Отход.** Видимый вооружённый враг (юнит или здание с оружием) в 6 клетках — разведчик бежит к старту. Вылазка брошена, следующая — через треть интервала.
- **Без лишних команд.** Приказ на клетку, куда разведчик уже идёт или где стоит, не повторяется. Ни одной отброшенной команды.
- **Память: `LastEnemyCell`** — где враг был виден последний раз. Нужна планировщику: «к врагу» (`BasePlacement.Target`) теперь — здания, армии, последнее место врага и только потом возможный старт. Без этого, когда разведчик снимал все старты, тесла-башня на картах на четверых смотрела в пустой угол.
- **`AiSettings`:** `ScoutingInterval`, `ScoutBlockCells` = 16, `ScoutDangerCells` = 6. В YAML — шаг 14.
- **Замеры** (бот против неподвижного человека): враг найден — Frozen Crossing 0:27, Taiga Front 2:17, Four Corners 0:58; разведано к 15-й минуте — Frozen Crossing 63 %, Taiga Front 35 %, Four Corners 26 %. Большие карты на четверых вылазки раз в 3 минуты обходят медленно — это темп «Среднего» из M8.

**Отряды (`SquadManager`):**

| Состояние отряда | Поведение |
|---|---|
| Сбор | Новые юниты идут в точку сбора у базы |
| Готов | Сила ≥ порога атаки → стратег разрешает атаку |
| Движение | Атака-движением к цели, держась вместе (ждут отстающих) |
| Бой | Фокус огня на ближайшей опасной цели, раненые отходят назад отряда |
| Отступление | Сила < 30% от начальной → назад к базе |

**Выбор цели атаки** (по памяти): харвестеры и ОПЗ → оборона на пути → производственные здания → стройплощадка. «Средний» не делает обходных манёвров — идёт кратчайшим путём.

**Сила отряда** = сумма `стоимость × здоровье / максимальное_здоровье` по юнитам. Сила врага оценивается по видимым юнитам и памяти.

**Как сделано (шаг 8).**
- **`Squads/Squad`** — номер, юниты, состояние (`SquadState`), цель (здание из памяти и/или клетка), сила сейчас и при выходе, точка перегруппировки, флаг `Beaten`. Отряды лежат в `AiPlan.Squads` — для стратега, обороны и оверлея.
- **`Modules/SquadManager`** (раз в 15 тиков). Каждый боец, кроме разведчика и харвестеров, — в отряде.
- **Сбор.**
  - Новые юниты — в собирающийся отряд.
  - Точка сбора — в 6 клетках от старта к врагу (`AiMemory.LikelyEnemyCell` — та же сторона, куда смотрит тесла-башня) или ближайшая клетка, куда пройдут и танк, и пехота.
  - Стоящий дальше 4 клеток получает атаку-движение к ней.
- **Готов и выход.**
  - Юнитов нужно `MinAttackArmy` = 8, на каждую следующую волну ×1,25: 8, 10, 12, 15.
  - Сила — не меньше `AttackThresholdPercent` = 100 % оценки врага. Оценка — армии из памяти и оборонительные здания (`стоимость × hp / max hp`).
  - Выходит, когда план разрешает (`AiPlan.AttackAllowed`; до стратега шага 9 — всегда). Без цели готовый отряд ждёт.
- **Цель.**
  - Здание из памяти по классу: ОПЗ → оборона → производство → стройплощадка → прочее. Внутри класса — ближайшее к отряду.
  - Зданий нет — где врага видели последний раз, потом ближайший возможный старт. Пришли туда, а там пусто — волна окончена, отряд идёт домой.
- **Движение.**
  - Атака-движением к цели.
  - Кто-то дальше 6 клеток от центра — перегруппировка: все атакой-движением к юниту ближе всех к центру, пока не соберутся в 3 клетках, но не дольше 20 с. Следующая — не раньше чем через 10 с.
  - Невооружённый враг рядом — харвестер, MCV — бьют его. Видимое здание-цель в 8 клетках — бьют его приказом атаки.
- **Бой** — вооружённый враг (юнит или здание с оружием) в 8 клетках от центра.
  - Приказ атаки на ближайшего — только тем, кто может его ранить (`TargetingSystem.CanHurt`, публичная обёртка без изменения поведения). Так у `AttackCommand` нет отказов.
  - Раненые (меньше 35 % hp) — один раз обычным движением на 3 клетки за центр, к дому.
- **Отступление.**
  - Сила ниже 30 % той, с которой вышли: `Beaten`, обычное движение — враги по пути не трогаются — на точку сбора.
  - Пришли — отряд вливается в собирающийся. Так же возвращается отряд, которому некого бить.
- **Без лишних команд.** Приказ того же вида на ту же точку или цель не повторяется, пока юнит его выполняет. Одинаковые приказы отряда идут одной командой.
- **`AiSettings`:** `MinAttackArmy`, `AttackGrowthPercent`, `AttackThresholdPercent`, `RetreatAtStrengthPercent`, `GatherCells`, `SquadSpreadCells`, `EngageCells`, `WoundedPercent`. В YAML — шаг 14.
- **Замеры** (бот против неподвижного человека, первая волна — 8 юнитов):
  - Frozen Crossing — выход в 9:37, все юниты человека уничтожены к 10:36;
  - Four Corners — выход в 10:48;
  - Taiga Front — выход в 13:48: экономика на больших картах медленнее.

  Ни одной отброшенной команды. Против 6 Носорогов, выданных человеку в момент выхода, волна теряет силу, к 10:36 отступает, четверо выживших вливаются во второй отряд. Вторая волна ждёт силы больше армии Носорогов в памяти.

**Оборона:**
- событие `UnderAttack` по своей базе (из M4) → оценка угрозы;
- угроза больше силы обороны → стратег переходит в «Оборону», ближайшие отряды возвращаются;
- угроза снята (врагов у базы нет 10 секунд) → возврат к предыдущему состоянию.

**Как сделано (шаг 5).**
- **Порядок постройки — запись данных `kind: build_order`** в `game/data/ai/union.yaml` (`faction`, `steps`), а не `buildOrders:` из плана. Загрузчик читает каждый `.yaml` под `game/data` как записи с видом, так что порядок — обычные данные:
  - ошибки — с файлом и строкой; шаги — здания своей фракции;
  - порядок входит в хеш данных: бот на каждой машине партии должен строить одинаково (M9).

  Пометка «лицом к врагу» не нужна: `BasePlacement` ставит любую оборону к вероятному врагу. Порядок выбирает `AiSettings.BuildOrder` (`standard`).
- **`Modules/BuildPlanner`** — что заказать, по важности:
  1. срочное экономики — реактор, ОПЗ;
  2. следующий невыполненный шаг порядка. Выполнен — когда таких зданий (стоят, растут, в очереди) столько же, сколько в порядке до этого шага; потерянное строится заново. Шаг с ещё растущим пререквизитом ждут — ничего после него не идёт вперёд;
  3. остальное экономики — завод для харвестеров;
  4. после порядка — ОПЗ до `MaxRefineries`, второй завод при деньгах ≥ 4000.

  Заказ — только если кредиты минус то, что очереди ещё должны заплатить (цена − `Paid`), покрывают цену. Если денег нет — ждать, не строя дешёвое вперёд. По заказу на очередь (здания, оборона) за ход.
- **`Modules/BasePlacement`** — кандидаты по кольцам до 14 клеток от середины стройплощадки, не больше 400 за вызов, поиск продолжается на следующем.
  - **Отбрасываются:** не встаёт по правилам в разведанном (`CanPlace`); ближе 2 клеток к краю; своё здание в кольце вокруг; клетка выхода или дока непроходима.
  - **Оценка:** до стройплощадки; ОПЗ — до разведанной руды (руда собирается раз на поиск); оборона — до точки в 6 клетках к вероятному врагу (здание или армия из памяти, иначе возможный старт).
  - **Проходы:** у лучших (до 8) проверяются заливкой по области базы — каждый выход и док своих зданий и нового должен соединяться с краем области. Перед проверкой место смотрится заново: база могла измениться за время поиска.
- **Отложено:** оборона на направлении атак — с `DefenseManager` (шаг 9).

**Составы армии (`compositions/union.yaml`):** роли (`anti_infantry`, `anti_armor`, `main_battle`, `anti_air`) и проценты; роли привязаны к юнитам Союза.

**Как сделано (шаг 6).**
- **Состав армии — запись данных `kind: army`** рядом с порядком, в `game/data/ai/union.yaml`:
  - `shares` — доли юнитов (Носорог 40 %, призывник 25 %, ракетчик 20 %, флак-трак 10 %, тесла-танк 5 %);
  - `against_infantry` и `against_vehicles` — кому идёт сдвиг.

  Роли плана сведены к прямым долям юнитов. ПВО (`anti_air`) не нужна до авиации M11. Проверка: доли — юниты фракции, в сумме 100 %, списки сдвига — из них. Состав входит в хеш данных.

  - **цель** — доли того, что можно строить сейчас (есть фабрика категории, открыт пререквизит). Доли не растягиваются на 100 %, иначе казармы до постройки завода превращают все деньги в пехоту — так было в первом прогоне: 25 пехотинцев и опоздавший на 2 минуты завод;

### 4.8. Условия победы и поражения (`VictorySystem`)

| Режим | Игрок проигрывает, когда |
|---|---|
| **Обычный** (по умолчанию, как в RA2) | Нет ни одного здания (кроме стен) **и** ни одного юнита |
| **Короткая игра** (опция) | Нет ни одного здания (кроме стен); MCV считается зданием |

- Проверка раз в 15 тиков. Поражение → событие `PlayerDefeated`, оставшиеся стены и юниты проигравшего уничтожаются (как в RA2), сетка видимости отключается.
- Партия заканчивается, когда в живых остались игроки одной команды → событие `MatchEnded` с победителями.
- Нейтральный игрок (`PlayerId.Neutral`, 0) и его здания — дома и техздания карты из M7, шаг 7 — в проверке не участвуют: он не проигрывает и не мешает закончить партию.
- Игрок может **сдаться** командой `SurrenderCommand` — та же логика поражения.
- Состояние «проиграл» входит в контрольную сумму.

### 4.9. Статистика партии (`MatchStats`)

|---|---|

  - `Problem(...)` — почему партию нельзя играть, или null.
- **Клетка старта — в самом описании.** `MapGrid` стартов не знает; «случайный» старт выбирает тот, кто собирает партию.
- **`MapId` — только метка.** Сама карта по-прежнему пишется в повтор: карты редактора и случайные по id не восстановить.
- **Вместо блока настроек** — `SimulationSettings.Match` и `SimulationSettings.ForMatch(setup, map)`: seed и кредиты берутся из описания. `GameSimulation` отказывает в партии, которую нельзя играть.
- **Повтор v17:** блок описания после блока карты. Seed и кредиты в нём не повторяются — они в заголовке.
- **Стартовое состояние — `MatchStart`, юниты создаёт мир, без команд**; повтор воссоздаёт их из описания:
  - фракция игрока;
  - MCV на клетке старта;
  - 3 призывника в одной клетке — ближайшей вне пятна стройплощадки (от кольца 2 для 3×3), куда пехота может встать. Развёртыванию они не мешают.
- **Пока только хранятся и пишутся в повтор:** `Team` (победа — шаг 10, союзники — M6/M8), `ShortGame` (шаг 10), `GameSpeed` (клиент M6).
- **Клиент:**
  - `MatchSetups.OneOnOne`: человек на старте 1, синий; бот «Средний» на старте 2, красный; свободные старты закрыты; новый seed на каждый запуск;
  - `SimulationHost`: аргумент `match` (быстрый скирмиш) — или описание строится само для любой `.rtsmap` с ≥ 2 стартами (редактор, `--map`, решение владельца). Тогда `MatchBots.AttachAll`, `LocalPlayer` — человек, камера над его стартом. **R** — та же партия с тем же seed. Песочница и `.txt` — как раньше;
  - `PlayerPalette`: 8 цветов из описания; без описания — цвет слота, так что P1 синий, P2 красный, как было. Им пользуются юниты, здания и миникарта вместо трёх копий;
  - «Быстрый скирмиш» — `scenes/debug/QuickSkirmish.tscn`, кнопка «Quick Skirmish (debug)» в главном меню (решение владельца): карты со стартами, сначала на двоих, превью, Start.
- **Найдено:** старты `relief_test` (тестовая карта рельефа M7) на склонах. MCV там сразу не развернуть (`NotFlat`) — его надо отвести.

### 4.12. Тестовая карта

До редактора и формата карт M7 используется тестовая карта из M3, дополненная двумя стартовыми позициями и симметричными полями руды. Описание стартов — в коде тестовой карты.

**Как сделано (шаг 2):** M7 закрыта раньше — играются готовые `.rtsmap` со стартами: Frozen Crossing (M3), Twin Rivers, Taiga Front, Four Corners. Тест `QuickSkirmishMapsTests` проверяет, что на каждой обе стороны встают и разворачиваются.

### 4.13. Отладочный оверлей ИИ

`AiDebugSnapshot` — неизменяемый снимок, который бот обновляет при каждом «мышлении»; клиент только читает его:

- текущее состояние стратега и приоритеты;
- следующая постройка и выбранная клетка;
- отряды: состав, состояние, цель (линии на карте);
- память: призраки вражеских зданий, оценка армии врага;
- деньги и энергия глазами бота.

Включается клавишей F12 (только отладочная сборка). Окно с подробностями — Shift+F12 (M8, раздел 4.9). F3 и F11 заняты: закладка камеры (M2) и переключение игрока (M4). Не влияет на симуляцию.

## 6. Тесты

### Модульные

| Область | Что проверяем |
|---|---|
| Расписание | Модули вызываются на правильных тиках со сдвигами |
| `AiWorldView` | Вражеские сущности в тумане не видны; свои и союзные — видны |
| `AiMemory` | Здание запоминается, забывается, когда место снова увидели пустым |
| `BasePlacement` | Не ставит на руду и занятые клетки; не перекрывает проход; детерминированный выбор при равенстве |
| `EconomyManager` | Решение строить реактор при нехватке энергии; восстановление харвестера |
| `ProductionManager` | Сдвиг состава при пехотной армии врага |
| `Squad` | Переходы состояний по силе |
| `VictorySystem` | Обычный режим, короткая игра, стены не считаются, сдача, команды |
| `MatchStats` | Подсчёт по событиям |

### Сценарные (без клиента)

| Сценарий | Ожидание |
|---|---|
| Бот против пассивного игрока (MCV не развёрнут) | Бот побеждает до 15-й минуты (тик 13 500) |
| Бот против пассивного игрока с базой и обороной | Бот побеждает до 25 минут |
| Бот против бота, 20 разных seed | Каждая партия заканчивается победой одного из ботов до 40 минут, нет исключений и «застреваний» (обе армии стоят дольше 5 минут) |
| Бот без денег (стартовые 0, руды нет) | Не падает, не делает невалидных команд |

### Детерминизм

- Бот против бота: два прогона с одним seed — одинаковые суммы на каждом тике.
- Повтор партии бот против бота: проигрывание записанных команд даёт те же суммы.
- Режим «перезапустить ботов»: команды ботов совпадают с записанными.
- Анализатор запрещённых API на `Rts.AI` срабатывает на `double`.

### Защита от неверных команд

Тест-обёртка считает отброшенные проверкой команды бота. Ожидание — **ноль** за всю партию: бот не должен пытаться делать невозможное (это признак ошибки в логике).

**Как сделано (шаг 4):**
- **`GameSimulation.RefusedCommands`** — команды, после которых `CommandProcessor.Apply` ничего не изменил. Это диагностика: в хеш не входит, растёт только на ошибках.
- **Команды бота среди них** — по игроку и номеру от `AiTurn.FirstSequence`.
- **Сценарии бота** требуют, чтобы таких не было: бот не шлёт ни отказанного, ни пустого.
