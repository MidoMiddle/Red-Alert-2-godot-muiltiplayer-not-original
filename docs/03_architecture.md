# 03. Архитектура движка и симуляции

> Статус: черновик · Создан: 2026-10-21
> Родительский документ: [00_concept.md](00_concept.md), блок 3

Фундамент проекта. Ошибки здесь дороже всего: переделывать архитектуру потом означает переписывать всю игру. Главная цель — **детерминированная симуляция**, которая одинаково считается на любом компьютере, чтобы работали мультиплеер, повторы и отладка.

---

## 1. Общая схема

```
┌─────────────────────────────────────────────────────────┐
│                     Godot (клиент)                      │
│                                                         │
│   Ввод ──► Команды ──┐          ┌──► Отображение (3D)   │
│   (мышь,             │          │    Звук, эффекты, UI  │
│    клавиатура)       ▼          │                       │
│               ┌──────────────────────┐                  │
│   Бот ──────► │  Симуляция (чистый   │ ──► События      │
│               │  C#, детерминизм)    │     (выстрел,    │
│   Сеть ─────► │                      │      взрыв,      │
│               └──────────────────────┘      готово)     │
└─────────────────────────────────────────────────────────┘
```

- **Симуляция** — сердце игры. Получает команды, делает тик, выдаёт новое состояние и события. Ничего не знает о Godot, графике и звуке.
- **Отображение** — читает состояние симуляции и рисует его. Интерполирует между тиками для плавности.
- **Источники команд** — игрок, бот, сеть, файл повтора. Для симуляции они неразличимы.

## 2. Проекты в решении

| Проект | Что внутри | Зависит от |
|---|---|---|
| `Game.Simulation` | Мир, сущности, правила, бой, экономика, поиск пути | Ничего (чистый .NET) |
| `Game.Data` | Загрузка определений юнитов, зданий, оружия из файлов данных | `Simulation` |
| `Game.AI` | Боты | `Simulation` |
| `Game.Net` | Lockstep, протокол, сериализация команд | `Simulation` |
| `Game.Client` | Godot-проект: отображение, ввод, UI, звук | Всё выше |
| `Game.Server` | Лобби и ретранслятор (позже) | `Net` |
| `Game.Tests` | Модульные тесты и тесты детерминизма | `Simulation`, `AI`, `Net` |

## 3. Детерминизм

**Правила, которые нельзя нарушать в симуляции:**

1. **Никакого `float` и `double`.** Только целые числа и фиксированная точка.
   - Позиции — в «лептонах», как в RA2: 1 клетка = 256 единиц.
   - Дробные величины (скорость, углы, проценты) — собственный тип `Fixed` (64-битное целое, 16 бит дробной части).
   - Тригонометрия и квадратный корень — через таблицы и целочисленные алгоритмы.
2. **Собственный генератор случайных чисел** с общим seed. Никакого `System.Random` и `Godot.GD.Randf`.
3. **Стабильный порядок.** Сущности обходятся по ID. Никаких перечислений `Dictionary`/`HashSet` в логике без сортировки.
4. **Никакого времени и окружения.** Симуляция не читает часы, файлы, сеть и настройки во время тика.
5. **Никакой многопоточности внутри тика** (по крайней мере пока не доказано, что это детерминированно).

**Проверка:** контрольная сумма состояния каждые N тиков. Тест: два прогона одного повтора на Mac и Windows дают одинаковые суммы.

---

## 4. Тики и время

- **Тик симуляции:** фиксированный, около 15 тиков в секунду (уточняется под ощущение темпа RA2).
- **Отрисовка:** 60+ FPS, с интерполяцией позиций между тиками.
- **Скорость игры:** меняется числом тиков в секунду, логика тика не меняется.
- **Задержка ввода:** команда исполняется на тике `текущий + N`. В одиночной игре N минимален, в сети подстраивается под пинг.

---

## 5. Команды

Всё, что меняет мир, — команда:

| Пример | Параметры |
|---|---|
| `Move` | юниты, точка, режим (обычный / атака-движение) |
| `Attack` | юниты, цель |
| `Build` | тип здания, клетка |
| `Produce` / `CancelProduction` | фабрика, тип юнита |
| `Sell`, `Repair` | здание |
| `Deploy` | юнит (MCV, IFV и т. п.) |
| `UseSuperweapon` | тип, точка |

Каждая команда: номер игрока, тик исполнения, компактная бинарная сериализация. Поток команд — это одновременно сетевой протокол и формат повтора.

---

## 6. Модель мира

- **Сущности:** юниты, здания, снаряды, эффекты-с-логикой (радиация, ящики). У каждой — стабильный ID.
- **Подход:** простые классы с компонентами по необходимости. Полноценный ECS — только если упрёмся в производительность.
- **Карта:** сетка клеток с высотами, типом земли, проходимостью, рудой, занятостью.
- **Пространственный индекс** для быстрых запросов «кто рядом» (сетка-бакеты).
- **Определения отдельно от экземпляров:** «Тяжёлый танк» (данные) ≠ «танк #1532» (экземпляр).

---

## 7. Связь симуляции и отображения

- Симуляция выдаёт **события** (выстрел, попадание, смерть, постройка завершена) — отображение проигрывает эффекты и звуки.
- Отображение **никогда не меняет** состояние симуляции. Только через команды.
- Для каждой сущности симуляции — визуальный узел Godot (пул объектов, чтобы не создавать заново).

---

## 8. Данные

- Определения юнитов, зданий, оружия, брони — в файлах **YAML**.
- Загружаются при старте и превращаются в неизменяемые определения.
- В сетевой игре — хеш данных сверяется у всех игроков перед стартом.
