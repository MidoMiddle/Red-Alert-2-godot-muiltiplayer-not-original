# Файлы данных `game/data`

> Для тех, кто правит баланс. Создан: 2026-10-22 (закрытие M3), бой — M4, шаг 1. Подробности реализации и решения — [M3_base_economy.md](../implementation/M3_base_economy.md), 4.1–4.5; [M4_combat.md](../implementation/M4_combat.md), 4.3.

Все игровые параметры юнитов, зданий, экономики, земли и передвижения лежат в YAML-файлах в `game/data`. Игра читает их при старте, баланс правится без перекомпиляции.

Проверить данные без запуска игры:

```bash
dotnet run --project tools/Rts.MapTool -- rules
```

Команда печатает число записей и хеш данных или список всех ошибок. Темп экономики на текущих данных — `dotnet run --project tools/Rts.MapTool -- economy frozen-crossing`.

---

## 1. Где что лежит

```
game/data/
├── shared/
│   ├── locomotors.yaml     типы передвижения
│   ├── terrain.yaml        типы земли: код карты, можно ли строить, скорости
│   ├── templates.yaml      абстрактные шаблоны (base_infantry, base_vehicle, base_building, base_defense)
│   └── economy.yaml        общие правила экономики (ровно одна запись)
├── combat/                 бой (M4)
│   ├── armor.yaml          типы брони
│   ├── warheads.yaml       боеголовки: доля урона по каждой броне, площадь
│   └── projectiles.yaml    снаряды: как долетают
├── factions/
│   ├── factions.yaml       фракции
│   └── union/
│       ├── buildings.yaml
│       ├── units.yaml
│       └── weapons.yaml    оружие юнитов и обороны
└── maps/                   готовые карты (формат — rtsmap.md)
```

Раскладка по файлам — для удобства людей: загрузчик читает все `*.yaml` под `game/data` и собирает записи вместе (карты — файлы `.rtsmap`, их он не читает). Порядок файлов и записей ни на что не влияет.

## 2. Записи

Файл — словарь записей. Ключ верхнего уровня — `id` записи: латиница в нижнем регистре, цифры и `_`. Он уникален во всех файлах и во всех видах: броня `flak` и снаряд `flak` не уживутся.

```yaml
reactor:  # Tesla Reactor
  kind: building
  inherits: base_building
  name: Reactor
  faction: union
  cost: 600
  build_time: 25.2s
  hp: 750
  footprint: [2, 2]
  power: 150
  prerequisites: [construction_yard]
```

| Служебный ключ | Смысл |
|---|---|
| `kind` | Вид записи: `unit`, `building`, `weapon`, `locomotor`, `terrain`, `faction`, `economy`, `armor`, `warhead`, `projectile`. Обязателен (можно взять из шаблона) |
| `inherits` | `id` шаблона или другой записи того же вида: её ключи берутся как значения по умолчанию, свои ключи их переопределяют. Цепочки разрешены, циклы — ошибка |
| `abstract: true` | Шаблон: определения не создаёт, только наследуется |

Неизвестный ключ — ошибка (опечатка не пройдёт молча).

---

## 3. Значения

| Тип | Как писать | Пример |
|---|---|---|
| Целое | Целое число | `cost: 600`, `power: -50` |
| Проценты | Число со знаком `%` | `slope: 20%`, `sell_refund: 50%` |
| Время | Секунды с `s`; переводится в тики (15 в секунду), округляется | `build_time: 25.2s` → 378 тиков |
| Флаг | `true` / `false` | `turret: true` |
| Пятно, клетка | Пара целых `[x, y]` | `footprint: [3, 4]`, `exit_cell: [1, 4]` |
| Список `id` | `[a, b]` | `prerequisites: [war_factory, radar]` |
| Текст | Строка | `name: Heavy Tank` |

Дробные числа читаются в фиксированную точку без `float` — одинаково на всех платформах. Запятая вместо точки (`1,5`), экспонента (`1e3`) и лишние символы — ошибки.

## 4. Ключи по видам

Колонка «Нужен» — обязателен ли ключ в итоговой записи (после наследования).

### `unit`

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `faction` | `id` фракции | да | Чей юнит |
| `category` | `infantry` / `vehicle` | да | Очередь производства |
| `cost` | целое | да | Цена в кредитах |
| `build_time` | время | да | Время производства одной фабрикой при полной энергии |
| `hp` | целое | да | Прочность |
| `armor` | `id` брони | да | Тип брони: по нему боеголовка выбирает долю урона |
| `speed` | целое | да | Лептонов за тик (256 = клетка): скорость RA2 × 6 |
| `turn_rate` | целое | да | Поворот за тик в BAngle (65 536 = круг); 0 — мгновенно |
| `sight` | целое | да | Обзор в клетках |
| `locomotor` | `id` передвижения | да | Как ездит и где проходит |
| `placement` | `cell` / `subcell` | да | Техника — клетка, пехота — место в клетке |
| `turret` | флаг | нет (`false`) | Есть ли башня |
| `turret_turn_rate` | целое | нет (как `turn_rate`) | Поворот башни за тик в BAngle; 0 — мгновенно |
| `prerequisites` | список `id` зданий | нет | Что должно стоять готовым |
| `primary` | `id` оружия | нет | Основное оружие (RA2 `Primary`); без него юнит не стреляет |
| `secondary` | `id` оружия | нет | Второе оружие (RA2 `Secondary`), например по воздуху; только вместе с `primary` |
| `model`, `icon` | путь | нет | Для клиента; симуляция не читает |
| `harvest_capacity` | целое | нет (0) | Сколько кредитов руды везёт харвестер; > 0 — юнит добывает |
| `harvest_time` | время | нет | Время на одну стадию руды |
| `unload_rate` | целое | нет | Кредитов за тик при разгрузке |

### `building`

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name`, `faction`, `cost`, `build_time`, `hp` | как у юнита | да | |
| `category` | `building` / `defense` | да | Очередь производства |
| `footprint` | `[ш, в]` | да | Пятно в клетках, 1–6 по стороне |
| `power` | целое | нет (0) | > 0 — даёт энергию, < 0 — потребляет |
| `build_up` | время | нет (0) | Вырастание после установки; здание пока не работает |
| `adjacent` | целое 0–10 | нет (2) | Сколько клеток может быть между зданием и своей базой |
| `extends_base` | флаг | нет (`true`) | Можно ли ставить рядом с ним другие здания (у стен `false`: стена — база только для стен) |
| `produces` | список из `building`, `defense`, `infantry`, `vehicle` | нет | Что производит фабрика |
| `exit_cell` | `[x, y]` | нет | Клетка выхода юнитов от северо-западного угла (в пятне или рядом) |
| `dock_cell` | `[x, y]` | нет | Клетка дока харвестеров (в пятне или рядом); есть у ОПЗ |
| `radar` | флаг | нет (`false`) | Даёт миникарту при достатке энергии |
| `armor` | `id` брони | да | Тип брони здания |
| `primary` | `id` оружия | нет | Оружие обороны |
| `prerequisites` | список `id` | нет | Что должно стоять готовым |
| `model`, `icon` | путь | нет | Для клиента |

### `faction`

| Ключ | Смысл |
|---|---|
| `name` | Название |
| `mcv` | `id` юнита, который разворачивается в базу |
| `construction_yard` | `id` здания из MCV; заказать его нельзя |
| `refinery` | `id` ОПЗ: готовый даёт бесплатный харвестер |
| `harvester` | `id` харвестера |

### `economy` (ровно одна запись)

| Ключ | Тип | Смысл |
|---|---|---|
| `low_power_min_rate` | проценты 0–100 | Нижний предел скорости производства при дефиците энергии |
| `multiple_factory_bonus` | проценты ≥ 0 | Прибавка скорости за каждую следующую фабрику категории |
| `max_factory_rate` | проценты ≥ 100 | Предел скорости с несколькими фабриками |
| `ore_value`, `gem_value` | целое | Кредитов в одной стадии руды / самоцветов (12 стадий на клетку) |
| `ore_growth_interval` | время | Как часто руда растёт |
| `ore_growth_chance` | проценты | Шанс клетки дорасти на стадию |
| `ore_spread_stage` | целое 0–11 | С какой стадии клетка засеивает соседнюю |
| `ore_spread_chance` | проценты | Шанс засеять |
| `sell_refund` | проценты | Возврат при продаже на полной прочности |
| `repair_cost` | проценты | Цена полного ремонта от цены здания |
| `repair_rate` | целое | HP за тик ремонта |

### `weapon`

Цепочка боя, как в RA2: **оружие** знает, сколько и как часто, **снаряд** — как долетает, **боеголовка** — по чему и как сильно. Одну боеголовку используют многие виды оружия.

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `damage` | целое | да | Урон одного выстрела до брони |
| `reload` | время | да | Между выстрелами (RA2 `ROF` / 15 с: тик — кадр RA2) |
| `range` | клетки, дробное | да | Дальность, > 0 |
| `min_range` | клетки | нет (0) | Ближе цель нельзя; меньше `range` |
| `projectile` | `id` снаряда | да | Чем стреляет |
| `warhead` | `id` боеголовки | да | Что делает попадание |
| `burst` | целое ≥ 1 | нет (1) | Выстрелов в очереди |
| `burst_delay` | время | нет (0) | Между выстрелами очереди |
| `targets` | список из `ground`, `air` | нет (`[ground]`) | По кому стреляет |
| `report` | `id` | нет | Звук выстрела, для клиента |

### `armor`

Только `name`. Номер брони — её место по `id`; порядок записей ни на что не влияет. Союз: `none`, `flak`, `plate` (пехота), `light`, `medium`, `heavy` (техника), `wood`, `steel`, `concrete` (здания), `special_1`, `special_2` (про запас).

### `warhead`

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `verses` | словарь «броня: проценты» | да | Доля урона по каждой броне (RA2 `Verses`), 0–1000 %; перечислить **все** типы брони |
| `spread` | клетки, дробное | нет (0) | Радиус площади; 0 — только цель |
| `percent_at_max` | проценты 0–100 | нет (100 %) | Доля урона на краю площади |
| `wall_damage` | флаг | нет | Бьёт ли стены |
| `affects_air` | флаг | нет | Задевает ли авиацию в площади |
| `infantry_death` | `id` | нет | Как гибнет пехота, для клиента |

```yaml
ap_shell:  # RA2 AP
  kind: warhead
  name: Armor Piercing
  verses: { none: 25%, flak: 25%, plate: 25%, light: 75%, medium: 100%, heavy: 100%, wood: 65%, steel: 45%, concrete: 45%, special_1: 100%, special_2: 100% }
  spread: 0.3
  percent_at_max: 50%
  wall_damage: true
```

### `projectile`

| Ключ | Тип | Нужен | Смысл |
|---|---|---|---|
| `name` | текст | да | Название |
| `motion` | `instant` / `ballistic` / `homing` | да | Мгновенный, по дуге в точку, самонаводящийся |
| `speed` | целое | для летящих | Лептонов за тик |
| `arc` | клетки | нет | Высота дуги |
| `inaccuracy` | клетки | нет | Разброс точки падения |
| `turn_rate` | целое | для `homing` | Поворот за тик в BAngle |
| `lifetime` | время | для `homing` | Сколько летит, прежде чем упасть |
| `visual` | `id` | нет | Что рисует клиент |

### `locomotor`, `terrain`

| Вид | Ключи |
|---|---|
| `locomotor` | `name`, `slope` (проценты: замедление на склоне). Движку нужны все шесть: `foot`, `track`, `wheel`, `amphibious`, `naval`, `hover` |
| `terrain` | `name`, `code` (символ в картах), `buildable` (флаг), `speed` (словарь «передвижение: проценты», 0 — не проходит). Движку нужны все восемь типов земли |

## 5. Проверки и ошибки

Загрузчик собирает **все** ошибки сразу. Каждая — с файлом, строкой и колонкой:

```
game/data/factions/union/units.yaml:20:3: 'speed' of 'heavy_tank' must not be negative
```

Проверяется:
- **синтаксис:** YAML, значения, неизвестные ключи;
- **наследование:** нет шаблона, цикл; якоря YAML (`&`, `*`) запрещены — наследование только через `inherits`;
- **ссылки:** фракция, передвижение, пререквизиты; броня юнитов и зданий, их оружие; снаряд и боеголовка оружия; броня в `verses`;
- **диапазоны:** цены, время и прочность не отрицательные; `adjacent` 0–10; пятно 1–6; клетки выхода и дока в пятне или рядом; проценты экономики; у оружия перезарядка и дальность > 0, `burst` ≥ 1, `min_range` < `range`; `verses` 0–1000 % и по каждой броне; летящему снаряду — скорость, самонаводящемуся — ещё поворот и время жизни;
- **требования движка:** у фракции есть стройплощадка, ОПЗ, MCV и харвестер; все типы земли и передвижения на месте.

С ошибкой в данных игра не стартует: печатает ошибки и закрывается с кодом 1.

## 6. Хеш данных

Хеш данных (`DataHasher`) считается по значениям, а не по тексту: пробелы, комментарии, порядок файлов и записей его не меняют, любое число — меняет. Хеш пишется в повтор. Повтор, записанный на других данных, проигрывается с предупреждением. Тест `GameDataTests` закрепляет хеш `game/data`: правка данных требует обновить его в том же коммите. В сетевой игре хеш будет сверяться перед стартом.
