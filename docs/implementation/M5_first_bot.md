## 1. Цель и результат

**Цель:** первая настоящая партия. Против игрока играет бот, который строит базу, добывает руду, собирает армию, разведывает и атакует. У партии есть начало, условия победы и поражения и экран итогов.

**Что будет работать в конце вехи:**

1. Новый проект `Rts.AI`: бот работает **внутри детерминированной симуляции** и действует только командами.
2. Бот видит только то, что видит его игрок (туман войны), и помнит последнее увиденное.
3. Модули бота: стратег, экономика, планировщик построек, производство армии, разведка, тактика отрядов, оборона.
4. Уровень сложности «Средний» и характер «Сбалансированный». Параметры — в YAML, чтобы следующие уровни (M8) были настройкой, а не новым кодом.
5. Условия победы и поражения, событие конца партии.
6. Статистика партии и экран итогов.
7. Минимальный запуск скирмиша: 1 человек против 1 бота на тестовой карте.
8. Отладочный оверлей «что думает бот».

**Критерий из [01_vision.md](../01_vision.md):** хочется сыграть вторую партию, даже с заглушками вместо моделей.

**Почему интерфейс `IAiController` в симуляции, а реализация в `Rts.AI`:** симуляция не должна зависеть от ИИ (правило из [03_architecture.md](../03_architecture.md)), а ИИ зависит от симуляции. Симуляция вызывает ботов через интерфейс, конкретный проект подключается при создании партии.

## 4. Технические решения

### 4.1. Где бот работает

**Решение: бот — часть детерминированной симуляции.** Он запускается на каждом компьютере в сетевой игре одинаково, как в RA2.

| Вариант | Плюсы | Минусы | Выбор |
|---|---|---|---|
| Бот внутри симуляции на всех клиентах | Нет сетевой задержки и зависимости от хоста; бесплатная синхронизация | Код бота обязан быть детерминированным | **Да** |
| Бот только у хоста, команды по сети | Бот может быть недетерминированным | Задержка, зависимость от хоста, лишний трафик | Нет |

**Следствие:** к коду `Rts.AI` применяются **те же правила детерминизма**, что к симуляции: анализатор запрещённых API (`BannedSymbols.txt` из M0) подключается и к `Rts.AI`.

### 4.2. Место в тике

```
1. Применить команды тика T (людей и ботов — одинаково)
2. Системы симуляции (движение, бой, экономика, ...)
3. Удалить мёртвых
4. Боты думают: читают состояние после тика T, выдают команды на тик T + 1
5. T = T + 1, контрольная сумма
```

- Команды бота проходят через ту же `CommandQueue` и ту же проверку, что команды игрока. **Никаких прямых изменений мира.**
- `PlayerId` бота — обычный игрок; `Sequence` у бота свой, как у любого игрока.

### 4.3. Бюджет «мышления» без часов

Ограничивать бота по **времени** нельзя — время недетерминировано. Ограничиваем по **расписанию и счётчикам**:

| Модуль | Как часто | Сдвиг |
|---|---|---|
| Стратег | Раз в 15 тиков (1 с) | `playerId × 3` |
| Экономика | Раз в 15 тиков | `+1` |
| Планировщик построек | Раз в 15 тиков | `+2` |
| Производство | Раз в 15 тиков | `+4` |
| Разведка | Раз в 45 тиков | `+5` |
| Отряды (тактика) | Раз в 5 тиков | `+0` |
| Оборона | Раз в 5 тиков | `+3` |

- Сдвиги разносят работу модулей и разных ботов по разным тикам.
- Дорогие операции (поиск места для здания, оценка целей) ограничены **числом проверок за вызов** (например, не больше 200 клеток на поиск места), а не временем. Незаконченный поиск продолжается на следующем вызове.

### 4.4. Повторы и боты

**Решение:** повтор записывает команды ботов так же, как команды людей (с пометкой «бот»). При просмотре повтора боты **не запускаются** — используются записанные команды.

- Плюс: повтор не ломается при изменении кода бота (ломается только при изменении правил симуляции, как и раньше).
- Для тестов детерминизма есть режим «перезапустить ботов» — тогда команды ботов из повтора сравниваются с заново сгенерированными.

### 4.5. Мир глазами бота

`AiWorldView` — единственный способ бота читать мир:

- свои сущности — полностью;
- союзные — полностью;
- вражеские — **только в видимых клетках** по сетке видимости из M4;
- карта: рельеф и проходимость — только в разведанных клетках (в завесе бот, как и игрок, ничего не знает); для поиска пути в неразведанное используется предположение «проходимо», как у юнитов игрока;
- руда — только в разведанных клетках.

`AiMemory` хранит последнее увиденное:

| Что | Хранится | Забывается |
|---|---|---|
| Вражеские здания | Тип, позиция, тик наблюдения | Когда клетку снова увидели, а здания нет |
| Скопления вражеской армии | Центр, примерная сила, тик | Через 60 секунд |
| Стартовые позиции врагов | Из настроек карты: известны все возможные старты, но не какой занят | Когда разведан |

Это гарантирует честность: «Средний» бот не знает, где игрок, пока не найдёт его.

### 4.6. Модули бота

**Стратег** — конечный автомат верхнего уровня:

```
           ┌────────────┐
  старт ──►│  Развитие  │──── армия ≥ порога ───►┌─────────┐
           │ (опенинг)  │                        │  Атака  │
           └─────┬──────┘◄─── волна закончилась ─┴────┬────┘
                 │                                    │
        база атакована                       база атакована
                 ▼                                    ▼
           ┌────────────┐                       ┌──────────┐
           │  Оборона   │◄──────────────────────┤  Оборона │
           └────────────┘   угроза снята → назад└──────────┘
```

Стратег выставляет **приоритеты** для остальных модулей (сколько денег на экономику, армию, оборону), а не управляет юнитами напрямую.

**Экономика:**
- держит целевое число харвестеров: 2 на ОПЗ, максимум ОПЗ — по параметрам уровня;
- следит за энергией: при запасе меньше 20% планирует реактор;
- восстанавливает потерянные харвестеры и ОПЗ в первую очередь;
- отправляет харвестеров на поля, удалённые от известных врагов.

**Планировщик построек:**
- идёт по порядку постройки (build order) из YAML;
- после завершения порядка — правила «по потребности» (энергия, вторая фабрика, оборона на направлении атак);
- не начинает здание, на которое нет денег с учётом текущих трат.

**Размещение зданий (`BasePlacement`):**

```
1. Кандидаты — клетки по спирали от стройплощадки в радиусе строительства
2. Отбрасываем: занятые, непроходимые, перекрывающие руду, вплотную к краю карты
3. Оценка:
   + близость к стройплощадке
   + для ОПЗ — близость к ближайшему полю руды
   + для обороны — направление на известного/вероятного врага
   − перекрытие проходов (проверка: после размещения путь от фабрик к краю базы существует)
   − соседство с другими зданиями вплотную (оставляем проезды в 1 клетку)
4. Лучший кандидат; равные — меньший (Y, X)
```

**Производство армии:**
- целевой состав армии из `compositions/union.yaml` (проценты по ролям);
- «Средний» уровень учитывает видимый состав врага **грубо**: если у врага > 50% пехоты — сдвиг к давящей технике, если > 50% техники — к противотанковым;
- держит очереди фабрик заполненными, пока есть деньги и стратег разрешает.

**Разведка:**
- в начале партии — один дешёвый юнит к ближайшим возможным стартам врага;
- далее — периодическая проверка неразведанных полей руды и последних позиций врага;
- разведчик отступает при встрече с армией.

**Отряды (`SquadManager`):**

| Состояние отряда | Поведение |
|---|---|
| Сбор | Новые юниты идут в точку сбора у базы |
| Готов | Сила ≥ порога атаки → стратег разрешает атаку |
| Движение | Атака-движением к цели, держась вместе (ждут отстающих) |
| Бой | Фокус огня на ближайшей опасной цели, раненые отходят назад отряда |
| Отступление | Сила < 30% от начальной → назад к базе |

**Выбор цели атаки** (по памяти): харвестеры и ОПЗ → оборона на пути → производственные здания → стройплощадка. «Средний» не делает обходных манёвров — идёт кратчайшим путём.

**Сила отряда** = сумма `стоимость × здоровье / максимальное_здоровье` по юнитам. Сила врага оценивается по видимым юнитам и памяти.

**Оборона:**
- событие `UnderAttack` по своей базе (из M4) → оценка угрозы;
- угроза больше силы обороны → стратег переходит в «Оборону», ближайшие отряды возвращаются;
- угроза снята (врагов у базы нет 10 секунд) → возврат к предыдущему состоянию.

### 4.7. Данные бота

**Уровень сложности (`game/data/ai/difficulty.yaml`, секция `medium`):**

```yaml
difficulty: medium
thinkIntervals: { strategist: 15, squads: 5 }    # тиков
maxRefineries: 2
harvestersPerRefinery: 2
attackStrengthThreshold: 3000      # сила отряда для первой атаки
attackGrowthPerWave: 1.25          # каждая волна сильнее
retreatAtStrength: 0.3
reactionDelayTicks: 30             # задержка реакции на атаку базы (2 с)
scouting: true
counterComposition: coarse         # none | coarse | full (M8)
cheats: { income: 1.0, buildSpeed: 1.0, seesAll: false }
```

**Порядок постройки (`game/data/ai/buildorders/union/*.yaml`):**

```yaml
buildOrders:
  standard:
    - reactor
    - refinery
    - barracks
    - refinery
    - war_factory
    - reactor
    - radar
    - { building: tesla_coil, facing: enemy }
    - tech_center
```

**Составы армии (`compositions/union.yaml`):** роли (`anti_infantry`, `anti_armor`, `main_battle`, `anti_air`) и проценты; роли привязаны к юнитам Союза.

### 4.8. Условия победы и поражения (`VictorySystem`)

| Режим | Игрок проигрывает, когда |
|---|---|
| **Обычный** (по умолчанию, как в RA2) | Нет ни одного здания (кроме стен) **и** ни одного юнита |
| **Короткая игра** (опция) | Нет ни одного здания (кроме стен); MCV считается зданием |

- Проверка раз в 15 тиков. Поражение → событие `PlayerDefeated`, оставшиеся стены и юниты проигравшего уничтожаются (как в RA2), сетка видимости отключается.
- Партия заканчивается, когда в живых остались игроки одной команды → событие `MatchEnded` с победителями.
- Игрок может **сдаться** командой `SurrenderCommand` — та же логика поражения.
- Состояние «проиграл» входит в контрольную сумму.

### 4.9. Статистика партии (`MatchStats`)

Собирается **в симуляции** по событиям — нужна и для экрана итогов, и в будущем для рейтинга на сервере (M10) и повторов.

| Показатель | На игрока |
|---|---|
| Юнитов построено / потеряно / уничтожено | Да |
| Зданий построено / потеряно / уничтожено | Да |
| Кредитов собрано / потрачено | Да |
| Длительность партии | Общее |
| Временные ряды (раз в 30 с): кредиты, сила армии, число зданий | Да |

- Статистика **не входит** в контрольную сумму: она производная и на игру не влияет. Но считается детерминированно, поэтому совпадает у всех.

### 4.10. Экран итогов

- Баннер «Победа» / «Поражение».
- Таблица по игрокам: показатели из 4.9.
- Простой график силы армии во времени (по рядам).
- Кнопки: «Ещё раз» (тот же `MatchSetup` с новым seed), «Сохранить повтор», «Выход».
- Стиль — простой; финальный вид в духе RA2 — в M6.

### 4.11. Описание партии (`MatchSetup`)

```
MatchSetup
├── MapId
├── Seed
├── Options: startingCredits, shortGame, gameSpeed
└── Players[]
    ├── Slot           0..7
    ├── Kind           Human | Ai
    ├── AiDifficulty   (для ботов; в M5 только Medium)
    ├── Faction        union
    ├── Color          индекс цвета
    ├── Team           номер команды
    └── StartPosition  индекс старта на карте или «случайно»
```

- Сериализуется в повтор (заменяет блок `settings` формата повтора M0; версия формата повышается).
- В M5 создаётся из отладочного меню «Быстрый скирмиш»; полноценный экран — M6.
- **Стартовое состояние:** у каждого игрока MCV + 3 призывника. Опция «стартовые юниты», как в RA2, — в M6.

### 4.12. Тестовая карта

До редактора и формата карт M7 используется тестовая карта из M3, дополненная двумя стартовыми позициями и симметричными полями руды. Описание стартов — в коде тестовой карты.

### 4.13. Отладочный оверлей ИИ

`AiDebugInfo` — неизменяемый снимок, который бот обновляет при каждом «мышлении»; клиент только читает его:

- текущее состояние стратега и приоритеты;
- следующая постройка и выбранная клетка;
- отряды: состав, состояние, цель (линии на карте);
- память: призраки вражеских зданий, оценка армии врага;
- деньги и энергия глазами бота.

Включается клавишей F3 (только отладочная сборка). Не влияет на симуляцию.

## 5. Шаги реализации

| № | Шаг | Результат | Готово, когда |
|---|---|---|---|
| 1 | **Каркас `Rts.AI`** | Проект, `IAiController`, место в тике, анализатор запрещённых API | Пустой бот вызывается по расписанию; тест детерминизма с пустым ботом зелёный |

## 6. Тесты

### Модульные

| Область | Что проверяем |
|---|---|
| Расписание | Модули вызываются на правильных тиках со сдвигами |
| `AiWorldView` | Вражеские сущности в тумане не видны; свои и союзные — видны |
| `AiMemory` | Здание запоминается, забывается, когда место снова увидели пустым |
| `BasePlacement` | Не ставит на руду и занятые клетки; не перекрывает проход; детерминированный выбор при равенстве |
| `EconomyManager` | Решение строить реактор при нехватке энергии; восстановление харвестера |
| `ProductionManager` | Сдвиг состава при пехотной армии врага |
| `Squad` | Переходы состояний по силе |
| `VictorySystem` | Обычный режим, короткая игра, стены не считаются, сдача, команды |
| `MatchStats` | Подсчёт по событиям |

### Сценарные (без клиента)

| Сценарий | Ожидание |
|---|---|
| Бот против пассивного игрока (MCV не развёрнут) | Бот побеждает до 15-й минуты (тик 13 500) |
| Бот против пассивного игрока с базой и обороной | Бот побеждает до 25 минут |
| Бот против бота, 20 разных seed | Каждая партия заканчивается победой одного из ботов до 40 минут, нет исключений и «застреваний» (обе армии стоят дольше 5 минут) |
| Бот без денег (стартовые 0, руды нет) | Не падает, не делает невалидных команд |

### Детерминизм

- Бот против бота: два прогона с одним seed — одинаковые суммы на каждом тике.
- Повтор партии бот против бота: проигрывание записанных команд даёт те же суммы.
- Режим «перезапустить ботов»: команды ботов совпадают с записанными.
- Анализатор запрещённых API на `Rts.AI` срабатывает на `double`.

### Защита от неверных команд

Тест-обёртка считает отброшенные проверкой команды бота. Ожидание — **ноль** за всю партию: бот не должен пытаться делать невозможное (это признак ошибки в логике).

**Ручная проверка (игровой чек-лист):**

- [ ] Бот возвращает армию на защиту базы.
- [ ] Бот перестраивает потерянные харвестеры и ОПЗ.
- [ ] Опытный игрок побеждает «Среднего» бота, но ему приходится играть всерьёз; пассивный игрок проигрывает.
- [ ] Победа и поражение срабатывают, экран итогов показывает правильную статистику.
- [ ] «Ещё раз» запускает новую партию; повтор сохраняется.
- [ ] Отладочный оверлей (F3) показывает мысли бота.
- [ ] **Хочется сыграть вторую партию.**

## 8. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Недетерминизм в коде бота (сортировки, словари) | Средняя | Анализатор запрещённых API на `Rts.AI`, тест «два прогона» на каждом сценарии |
| Бот застревает (армия стоит, база не строится) | Высокая | Сценарии бот-против-бота с детектором застревания; оверлей мыслей для разбора |
| Размещение зданий перекрывает проходы | Средняя | Проверка пути после размещения, оставление проездов |
| Бот слишком слабый или слишком сильный | Высокая | Все пороги в секция `medium` в `difficulty.yaml`; настройка по игровым тестам |
| Производительность при думающих ботах | Низкая | Расписание, сдвиги, лимиты по числу проверок |
| Бот «читерит» случайно (доступ мимо `AiWorldView`) | Средняя | Модули получают только `AiWorldView`, без ссылки на `World`; ревью |
