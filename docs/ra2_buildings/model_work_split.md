# Модели зданий: что делает Haiku 5.5, а что Opus 5.5

> Статус: черновик · Создан: 2026-10-28
> Связанные документы: [обзор зданий](README.md), [гайд по генерации](generation_guide.md), [стандарт моделей](../art/model_standards.md), [реестр ассетов](../assets_registry.md)

Модель здания мы делаем скриптом Blender: один файл `tools/blender/buildings/<id>.py` на здание, общие запекание и экспорт — в `tools/blender/rts_common.py`. Образец — [tesla_coil.py](../../tools/blender/buildings/tesla_coil.py). Работа над моделью бывает разной сложности. Простую часть дешевле и быстрее отдать Haiku 5.5, сложную — Opus 5.5.

**Это оценка до пробы.** На моделях проекта Haiku 5.5 ещё не пробовали. Разделение ниже — исходное. Первые две-три модели Haiku покажут, где граница на деле; по ним документ поправим.

---

## 1. Правило

- **Opus делает первый образец.** Новый механизм (турель, ворота, вращающаяся тарелка, кран) и стиль фракции (палитра, панели, материал) сначала делает Opus. Это скрипт, с которого потом копируют.
- **Haiku повторяет по образцу.** Если похожая модель уже есть, Haiku копирует её скрипт под новый ID, меняет размеры, пропорции и цвета.
- **Haiku делает простое с нуля.** Здание без подвижных частей из коробок, цилиндров и плит, без узнаваемого силуэта.
- **Каждую модель Haiku смотрит Opus или владелец** по снимку галереи (раздел 4). Если Haiku дважды не справился с моделью, она переходит к Opus.

## 2. Виды работы

| Работа | Кто | Почему |
|---|---|---|
| Строка в `game/data/visuals/models.yaml`, запись в `docs/assets_registry.md` | Haiku | по образцу соседних строк |
| Прогон тестов таблицы моделей и снимок галереи | Haiku | готовые команды (раздел 4) |
| Пустые узлы `light_*`, `smoke_*`, `damage_*`, `fire_*`, `muzzle_*` по заданным координатам | Haiku | точка и имя, без формы |
| Копия скрипта под новое здание: новый ID, размер, высота, цвета | Haiku | структура уже есть |
| Статичный корпус из коробок, цилиндров, плит, труб на готовых функциях `Parts` | Haiku | примитивы с понятными размерами |
| Стена: один сегмент | Haiku | один блок на клетку |
| Зона цвета команды (`team_mask`) на готовом месте: флаг, полоса, панель | Haiku | отдельный меш по образцу |
| Первая модель фракции: палитра, материал, набор деталей | Opus | задаёт стиль для всех остальных |
| Новая функция в `Parts`: лофт, кривая, дуга, рифление, тор | Opus | пространственная геометрия, легко ошибиться в нормалях и швах |
| Подвижная часть с точкой вращения: `turret`, `barrel`, `gate`, `roof`, `spin_*`, краны | Opus (первая), дальше Haiku | ось и иерархия узлов должны совпасть со стандартом |
| Клипы `open`, `close`, `active` | Opus | клипов в моделях проекта ещё нет, формат не устоялся |
| Стекло, прозрачные колбы, светящиеся ёмкости | Opus | конвейер запекает один непрозрачный материал, прозрачность — новое |
| Органические формы Культа | Opus | не собираются из коробок |
| Здание на воде (верфи) | Opus | pivot на уровне воды, у проекта такого ещё нет |
| Узнаваемый силуэт: супероружие, главная оборона фракции | Opus | нужна оценка картинки и доводка пропорций |
| Состояния: повреждённое, покинутое, руины | Opus | своя геометрия разрушения ([civil_house.py](../../tools/blender/families/civil_house.py)) |
| Разбор ошибок запекания и экспорта, проверка по `look` и снимку | Opus | нужно найти причину, а не повторить шаг |

## 3. Здания

Обозначения в колонке «Кто»:

- **Haiku** — с нуля, простое здание;
- **Haiku по образцу** — Haiku копирует скрипт из колонки «Образец», когда тот готов;
- **Opus** — первый образец или сложное здание;
- **готово** — модель уже есть.

Размеры — из `prompts.md` зданий (часть рабочие). Подвижные части и узлы — оттуда же и из `animations.md`.

Затем первые модели Альянса и Культа (электростанция, биореактор) — Opus, после них большая часть фракции уходит Haiku.

## 4. Как проверить модель Haiku

1. Скрипт отработал в Blender без ошибок, `.blend` и `.glb` лежат по путям из [стандарта моделей](../art/model_standards.md), раздел 1.
2. Отчёт `glb_report`: треугольников ≤ 20 000, имена узлов — из `prompts.md` здания и раздела 4 стандарта, есть `team_mask`.
3. Размер по футпринту: модель не выходит за W×H клеток, pivot в центре на земле, перёд −Z.
4. Тест таблицы моделей:

   ```bash
   dotnet test tests/Rts.Data.Tests --filter ModelTable
   ```

5. Снимок галереи моделей. Смотрит Opus или владелец: силуэт читается, цвет команды на месте, ничего не висит в воздухе и не торчит сквозь корпус.

   ```bash
   /Applications/Godot_mono.app/Contents/MacOS/Godot --path game -- --ui-units --models --screenshot gallery.png --frames 30
   ```

## 5. Как запустить Haiku

- **Отдельная сессия.** Выбрать модель Haiku 5.5 в окне сессии и дать задание: здание, образец, этот документ и `prompts.md` здания.
- **Субагент из сессии Opus.** Opus ставит задачу субагенту с моделью Haiku и сам проверяет результат по разделу 4. Так удобнее для пачки похожих зданий: стены, статичные блоки нейтралов.

В задании для Haiku указывать: ID и размер здания, скрипт-образец, список узлов, палитру фракции ([гайд, раздел 4](generation_guide.md)) и «не коммитить».
